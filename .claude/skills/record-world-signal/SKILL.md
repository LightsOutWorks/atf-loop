# record-world-signal

HumanのWorld Signal報告を、該当台帳へ正しい等級・欠落なしで転記し、次の一手を1案起草して止まるスキル。**Humanから報告が渡された時だけ起動するオンデマンド処理**であり、観測の自動化ではない（X Reply Ingestionの自動観測はD-003でHOLD。本スキルはその領域に踏み込まない）。

## 位置づけ

- **入力はHuman報告のみ**: スクリーンショットの内容・文章・口頭メモ。harnessからのX読取は不可（E-008実測）であり、読みに行かない。
- **正本を複製しない**: 記録規律・凡例・Stage定義・文面規律の正本は各台帳と契約が持つ。実行のたびに該当台帳の規律を読む。本ファイルと正本が矛盾したら**常に正本が勝ち**、矛盾自体を欠陥として報告する。
- 記録の重さは対象の規律に従う。**このリポジトリはPUBLICである**——PII規律は転記前に必ず適用する。

## 手順

### 1. 対象の特定

`experiments/INDEX.md` のACTIVE実験から、報告が帰属する実験と台帳を特定する（返信・接触反応 → 接触系台帳（例: `experiments/batch-1/LEDGER.md`）/ プレイ・納品観測 → `experiments/desire-to-game/LEDGER.md`）。**特定できない場合はHumanに確認する。推測で割り当てない。** join key（contact id・participant id・元投稿URL・ファイルSHA-256等）が報告から取れない場合も同じ——聞くか `UNKNOWN` と書く。

### 2. 対象台帳の規律を読む

特定した台帳の運用規則・記録規律・凡例と、直近の関連記録（Reply Log・事前登録済みの判定条件）、必要なら当該実験の契約を読む。記録の列・分類・Stage語彙はすべて台帳側の定義に従う。

### 3. 等級付けと分離

- **FACT**: Human報告に含まれるverbatim・スクショ記載値・Humanが確認したと明言した事実。出典（報告日時・確認手段）を付けて記録する。
- **INFERENCE**: 解釈・分類・推定。必ずFACTと区別してラベルする。
- **UNKNOWN**: 報告に含まれない値。**補完しない。それらしい値・時刻・数値を発明しない。** 精度も落とさない——「昨日の夜」しか報告が無ければ、分単位の時刻を作らず日付レベル＋精度UNKNOWNで書く。
- 台帳が定める分離を適用する: **Expressed / Observed**（発言と行動の矛盾はObserved優先）、**Repair / Continuation**（E-014: Repair Requestは「次のDesire」にカウントせずRepair Request Logへ）、その他対象台帳固有の分離。

### 4. 転記（最小差分・追記のみ）

該当台帳へ最小差分で追記する。既存行・過去の記録は書き換えない（訂正は日付付き訂正追記）。verbatimは原文のまま保存する。日時・対象・join key・証拠等級を欠落させない（欠落する場合は `UNKNOWN` を明記して欠落自体を記録する）。**転記前にPII検査**——実名・顔・年齢・家族構成の特定につながる記述を書かない。E-014は匿名ID（P1〜）と続柄カテゴリのみ。

タイムアウト・判定窓に触れる記録では、**起点は送信時刻**で書く。送信はHuman Gateであり、受信から送信までの間隔は常に `UNKNOWN`（Batch 1 Reply Log 004の実測欠陥。受信時刻起点で絶対時刻を書かない）。事前登録済みの判定条件が存在する場合はそれに従い、結果を見てから窓を動かさない。

### 5. 整合検査（必要な場合のみ）

記録した事実が `CURRENT_STATE.md` の現在値（累積REPLY数等）や `experiments/INDEX.md` のstatus行と食い違う場合のみ、その箇所を指摘し、日付付き訂正追記を**提案**する。関係のない整合監査へ広げない。

### 6. 次の一手の起草（1案のみ）

台帳の規律・事前登録済みの判定条件・分類結果から、次の一手を**1案だけ**起草する（HI-11: 選択肢を並べて返さない）。返信文の既定は**40〜120字・質問1つ・オファーなし・リンクなし・自己紹介なし・毎回個別文面**（詳細な文面規律・撤退シグナルは対象台帳と `direction/SALES_OS_2026-08.md` が正本）。事前登録済みの分岐（「〜が返ったら閉じる」等)がある場合はそれに従い、**上書きしない**。

会話の往復をファネルの前進と読み替えない。Stageの変更は台帳の定義が根拠づける場合だけ差分として提案し、確定はHuman確認に委ねる。

### 7. 停止

起草を提示して止まる。**送信しない。**

## 停止線（常に適用）

行わないこと: 第三者への送信・投稿・DM（`CONSTRAINTS.md` Part I §4 Human Gate）/ X・SNSの読取・監視・ポーリング・API取得 / 常駐処理・スケジュール登録・通知の設定 / mainへのmerge / 支出。記録の反映はbranch上のcommitまでとし、PR作成は依頼の文脈に従う。mergeは常にHuman Gate。
