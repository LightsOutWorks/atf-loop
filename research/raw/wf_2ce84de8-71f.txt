## 4. AGENTS.md 規約の実際の仕様

> **調査上の制約（先に開示）**: egress proxy により `agents.md`、`developers.openai.com`、`github.blog`、`openai.com`、`docs.factory.ai`、`linuxfoundation.org` への直接 fetch が**すべてブロック**された。したがって一次ソースを逐語取得できたのは (a) Claude Code 公式ドキュメント、(b) GitHub 上の `agentsmd/agents.md` リポジトリ README と Issues、(c) VS Code / Copilot / Aider の GitHub Issues のみ。それ以外は検索結果スニペット経由の二次情報として明示的にラベルする。

### 4.1 規約そのもの ── 【事実・一次ソース】

`agentsmd/agents.md` リポジトリ README より逐語:

> "AGENTS.md is a simple, open format for guiding coding agents."
> "Think of AGENTS.md as a README for agents: a dedicated, predictable place to provide context and instructions to help AI coding agents work on your project."

README が示す標準例のセクションは3つだけ: **Dev environment tips / Testing instructions / PR instructions**。

**形式の厳密さ**: 【事実に近いが二次】素の Markdown であり、**必須フィールドなし・YAML frontmatter なし・独自構文なし**。見出しは任意で、エージェントは本文をそのままパースする。→ つまり「仕様」と呼べる規範的な文書は存在せず、実体は**慣習 + 例示**である。機械可読なスキーマは**存在しない**（一次ソースで schema を確認できなかった＝**不明**ではなく、README/サイトが「任意の Markdown」と言っている以上、存在しないと判断してよい）。

### 4.2 ガバナンス・採用規模 ── 【二次情報、複数ソース一致】

- Linux Foundation 傘下に **Agentic AI Foundation (AAIF)** が発足（2025-12）。Anthropic が MCP、OpenAI が **AGENTS.md**、Block が goose を寄贈。AGENTS.md は現在 AAIF がスチュワード。
- 採用規模: **60,000+ の OSS リポジトリ**。
- 一次ソース（openai.com / linuxfoundation.org のプレスリリース）は egress ブロックで逐語確認**できず**。数字は検索スニペット由来。

### 4.3 どのツールが読むのか ── 【ツールごとに確度が違う。一括りにするのは誤り】

| ツール | AGENTS.md をネイティブに読むか | 確度・ソース |
|---|---|---|
| OpenAI Codex | 読む（原産地） | 【二次】公式 docs は fetch 不可 |
| Cursor | 読む | 【二次】 |
| GitHub Copilot / VS Code | 読む | 【事実】VS Code に `chat.useNestedAgentsMdFiles` 設定が存在すること自体が読む証拠 |
| Google Jules / Gemini CLI / Devin / Factory / Amp / Zed / Windsurf | 読むとされる | 【二次】AAIF プレスリリースの採用者リスト（スニペット経由） |
| **Aider** | **ネイティブには読まない（要注意）** | 【事実】[Aider issue #4363](https://github.com/Aider-AI/aider/issues/4363) が「Aider は既定で `CONVENTIONS.md` を見る。`--conventions-file` で任意ファイルを指定できるので、docs で AGENTS.md を推奨してほしい」という**ドキュメント提案**として open。多数のブログが「Aider もネイティブ対応」と書いているが、**この一次ソースと矛盾する**。ブログ側が誤りである可能性が高い。 |
| **Claude Code** | **読まない** | 【事実・一次】下記 4.5 |

### 4.4 探索順序・ネスト ── 【規約は規定していない。実装依存】

規約サイトの主張（[issue #53](https://github.com/agentsmd/agents.md/issues/53) 内に引用された homepage 文言、逐語）:

> "Agents automatically read the nearest file in the directory tree, so the closest one takes precedence and every subproject can ship tailored instructions."

**しかし** issue #53（「monorepo で複数の agents.md がある時、root は無視されて nearest だけ使われるのか、それとも両方 merge されるのか」2025-09-11 提起）には**メンテナ回答が付いていない**。→ **root と nearest が merge されるのか、nearest が root を上書きするのかは規約として未定義＝不明**。

実装ごとの実測（確度別）:

- **Codex**【二次】: `~/.codex/AGENTS.override.md` → `~/.codex/AGENTS.md` → `<git-root>/AGENTS.override.md|AGENTS.md` → 中間ディレクトリ各段 → `<cwd>`。**root→leaf で連結し、cwd 側が競合に勝つ**。`--print-instructions` で実際にマージされた内容をダンプできる（2026-04 以降）。
- **VS Code**【事実+二次】: 設定 `chat.useNestedAgentsMdFiles` が存在。有効時はワークスペース配下を再帰探索して相対パスをチャットコンテキストに追加する。既定 ON かどうかは**二次情報が「GA・既定 ON」と言うが一次確認できておらず不確実**。
- **GitHub Copilot（CLI / multi-root workspace）**【事実】: ネスト未対応。[agents.md issue #153](https://github.com/agentsmd/agents.md/issues/153)（open）— 「ネストした AGENTS.md で作業中フォルダの正しいファイルを読まない。nested hierarchy に対応しているのは `.github/copilot-instructions` だけ」。[copilot-cli issue #3051](https://github.com/github/copilot-cli/issues/3051) も open。
- **[microsoft/vscode #266120](https://github.com/microsoft/vscode/issues/266120)**: サブフォルダ探索・親ディレクトリ探索を「これから追加する」機能として列挙。

→ **結論（事実）**: 「nearest wins」は規約の**願望**であって保証ではない。root に置いたものは全ツールが読むが、サブディレクトリのものは**読むツールと読まないツールが混在する**。

### 4.5 CLAUDE.md との併存 ── 【事実・一次ソース、ここが最も確実】

[Claude Code 公式ドキュメント](https://code.claude.com/docs/en/memory) の "AGENTS.md" セクション、逐語:

> "Claude Code reads `CLAUDE.md`, not `AGENTS.md`. If your repository already uses `AGENTS.md` for other coding agents, create a `CLAUDE.md` that imports it so both tools read the same instructions without duplicating them."

公式が示す2つの方法:

```markdown
@AGENTS.md

## Claude Code

Use plan mode for changes under `src/billing/`.
```

```bash
ln -s AGENTS.md CLAUDE.md
```

補足（すべて一次・逐語相当）:
- symlink は Windows では管理者権限か Developer Mode が必要 → **クロスプラットフォームなら `@AGENTS.md` import を使う**。
- `/init` は既定では Cursor rules と `.github/copilot-instructions.md` を読む。`CLAUDE_CODE_NEW_INIT=1` を立てると **`AGENTS.md`、`.devin/rules/`、`.windsurf/rules/`、`.clinerules` も読む**。
- `/import` コマンド（v2.1.213+）は `AGENTS.md` 等を **CLAUDE.md へ一度きりコピー追記**する（同期はしない）。
- 「Claude Code は AGENTS.md をフォールバックとして読む」という巷の説は**公式ドキュメントの文言と矛盾する＝誤り**。

参考: CLAUDE.md 側の探索は「cwd から**上へ**walk、見つかった全ファイルを**上書きではなく連結**、root→cwd 順。サブディレクトリの CLAUDE.md は起動時ではなく**そのディレクトリのファイルを読んだ時に遅延ロード**」。AGENTS.md の nearest-wins とは**意味論が違う**（Claude は merge、AGENTS.md 陣営は override 志向）。

### 4.6 推奨される中身と長さ ── 【相場】

| 出典 | 数値 | 確度 |
|---|---|---|
| Claude Code 公式 | CLAUDE.md は **200行未満を目標**。「Longer files consume more context and reduce adherence」。長さ制限は強制されず全文ロードされる | 【事実・一次】 |
| GitHub Blog「2,500+ リポジトリからの教訓」 | **150行超は逓減**、推論コストが **20〜23%** 増えるのに性能は上がらない | 【二次・原文 fetch 不可】 |
| 同 | 上位層が押さえる6領域: **commands / testing / project structure / code style / git workflow / boundaries**。まず 20〜30行から | 【二次】 |
| 同 | Boundaries は **✅ Always / ⚠️ Ask first / 🚫 Never の三段ガードレール**が破壊的ミス防止に最も効く。最頻の有効制約は "Never commit secrets" | 【二次】 |
| Cursor | 500行未満推奨 | 【二次】 |
| 実践例 | HumanLayer は 60行未満。1セクションが 200行を超えたらサブディレクトリへ分割 | 【二次】 |

内容面の共通助言【二次】: 「show, don't tell」— 規約1つにつきコード例1つのほうが説明3段落より効く。検証可能な具体性（"Use 2-space indentation" > "Format code properly"）。

### 4.7 「AGENTS.md に書くべきでない」とされるもの ── 【二次情報】

1. **secrets / credentials / private token / private hostname**（公開リポジトリなら特に致命的）
2. **他所にある長文ドキュメントの全文コピー**（参照にする）
3. **陳腐化するディレクトリ棚卸し**（リポジトリと drift する）
4. **エージェント自身に `/init` で書かせた AGENTS.md**（GitHub のデータでは「助けるより害になる」とされる）
5. 【一次・Claude 公式の類推】ツール固有の設定・強制したいルール。強制は AGENTS.md/CLAUDE.md ではなく **hook / permissions** の仕事。「CLAUDE.md instructions shape Claude's behavior but are not a hard enforcement layer」

### 4.8 不明と明記すべき点

- root と nearest の **merge か override か**は規約未定義。ツール依存（Codex=連結+cwd優先、VS Code=文脈追加、Copilot=未対応）。
- VS Code の `chat.useNestedAgentsMdFiles` の**既定値**（二次情報は既定 ON と言うが未検証）。
- **Jules / Gemini CLI / Devin の探索順序の実測**は未確認。
- GitHub Blog の統計値の**原文**（150行、20〜23%、2,500+ リポジトリ）は fetch 不可のため未検証。
- AGENTS.md に**バージョン番号や適合性テストが存在するか**は確認できず（おそらく存在しないが、断定不可）。

## 5. 提案 ── `atf-loop` における AGENTS.md と CLAUDE.md の責務分割

### 5.1 このリポジトリ特有の脅威モデル（先に）

このリポジトリは**コードプロジェクトではなくガバナンス文書群**であり、かつ **PUBLIC** で、かつ **`.github/workflows/factory.yml` の schedule が今も毎週土曜 10:00 JST に自動発火する**。ここに AGENTS.md を置く実効的な意味は「ビルド手順の共有」ではなく、次の3つの事故を止めることである。

1. **Mission 誤読**: Codex / Cursor / Copilot が `works/seed-*` と `factory.yml` を見て「これはゲーム生成リポジトリ」と推定し、その方向に作業する。
2. **Human Gate 突破**: CONSTRAINTS.md を読まないエージェントが main へ merge、第三者へ送信、公開・不可逆操作を実行する。
3. **HOLD 資産の破壊的整理**: 「古い成果物だから削除・リファクタしましょう」と提案・実行される（seed-009 は**意図的に未修正**、schedule 停止は Human Gate）。

したがって AGENTS.md に最優先で書くべきは **Boundaries（🚫 Never）** であって、dev environment tips ではない。

### 5.2 分割の原理: 「1つの事実は1ファイルにしか書かない」

現状すでに **CLAUDE.md と README.md が Boot order を二重に持ち、Budget cap `JPY 50,000/月` が CONSTRAINTS.md と CLAUDE.md に二重に書かれている**。AGENTS.md を素朴に足すと三重になる。これを避ける唯一の構造は、**AGENTS.md を唯一の tool-agnostic なブートローダにし、CLAUDE.md は import 1行 + Claude 固有差分だけにする**こと。

### 5.3 具体案

**A. `AGENTS.md`（新設、root、40〜70行目標）** ── 全エージェント共通の唯一のブートローダ

| 載せる | 理由 |
|---|---|
| 「このリポジトリはゲーム工場ではない」+ 現 Mission 1文（D-001参照） | 誤読防止。最上部に置く |
| **正典の読み順**（CONSTRAINTS → OS → DESIRES → CURRENT_STATE → Task Contract） | ここが正典。CLAUDE.md からは消す |
| **🚫 Never**（三段ガードレール形式）: main への merge / 第三者への送信 / 支払い / credential 変更 / 公開・不可逆操作 は**すべて人間承認が必要**。`works/`・`factory.yml`・`index.html`・`smoke.mjs` は HOLD、削除・整理・リファクタ禁止。`factory.yml` の schedule 停止・変更禁止。seed-009 の失敗は意図的、修正禁止 | 事故を実際に止める部分 |
| ⚠️ Ask first / ✅ Always（例: 検証は `node smoke.mjs works/seed-001`、writing は `scripts/writing-check.py`） | 検証可能な具体命令 |
| Budget の**参照**（金額を書かず「上限は `CONSTRAINTS.md` Part I §4 が正典。AI による変更禁止」） | 数値の二重管理を断つ |

**B. `CLAUDE.md`（全面書き換え、5〜15行）**

```markdown
@AGENTS.md

## Claude Code 固有

（Claude Code だけに効く事項のみ。例: plan mode を使う対象、.claude/rules/ の運用、
auto memory の扱い、/context で読み込み確認、subagent への Task Contract 渡し方）
```

現在 CLAUDE.md にある本文（Mission / Boot order / Human Gates / Budget）は**すべて AGENTS.md へ移設し、CLAUDE.md からは削除**する。公式が明言する通りこれで「both tools read the same instructions without duplicating them」が成立する。symlink ではなく **`@AGENTS.md` import** を選ぶ理由: (1) Windows で権限不要、(2) Claude 固有節を後置できる、(3) PUBLIC リポジトリ上で symlink より意図が読める。

**C. `README.md`（人間向けに専念）**

README の「Boot Protocol」節は AGENTS.md と内容が重複する。二択:
- **推奨**: README の Boot Protocol を「エージェント向けの起動指示は `AGENTS.md` が正典」の1行 + 正典ファイル一覧表だけに縮め、順序の本文は AGENTS.md のみに置く。
- 代替: 人間の可読性のため README にも残す（重複を許容）。この場合「AGENTS.md 変更時は README も更新」という運用負債を明示的に受け入れること。

**D. 任意 ── `works/AGENTS.md`（1〜5行）**

`works/` 配下だけに「HOLD。編集・削除・修正禁止。理由は root の AGENTS.md」を置く。nearest-wins が効く Codex / Cursor / VS Code では最も強い防波堤になる。ただし **Copilot 系はネスト未対応（4.4 参照）なので、root の AGENTS.md にも同じ禁止を必ず書く**（これは唯一意図的に許容する重複）。

### 5.4 責務の境界を1行で

- **`AGENTS.md`** = 「どのエージェントも、作業を始める前に必ず従う制約と読み順」（tool-agnostic・命令形・Never 中心・40〜70行）
- **`CLAUDE.md`** = 「AGENTS.md を import した上で、Claude Code というツールでだけ意味を持つ差分」（5〜15行）
- **`README.md`** = 「人間が経緯と全体像を理解するための説明」（履歴・カタログ・リンク）
- **`CONSTRAINTS.md` 他の正典5ファイル** = 「事実と数値の単一情報源」（AGENTS.md はここへ**参照**するだけで転記しない）

### 5.5 導入後の検証手順

1. Claude Code セッションで `/context` を開き、**Memory files** に `CLAUDE.md` が出ること、import された `AGENTS.md` の内容が入っていることを確認。
2. Codex を使う場合は `--print-instructions` でマージ結果をダンプして確認（【二次情報】）。
3. AGENTS.md 新設 → main へ反映は **Human Gate（main merge）に該当**するため、ヒロの承認が必要。
