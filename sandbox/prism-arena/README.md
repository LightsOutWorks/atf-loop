## 遊びかた

中央の鉱脈から一定間隔でクリスタルが出る。拾って **チーム合計10個を15秒間保持**すれば勝ち。倒されると持っているクリスタルをその場に落とす。制限時間150秒で決着がつかない場合は、保持数が多いチームの勝ち。

| | 操作 |
|---|---|
| **PC** | `WASD` / 矢印キーで移動、マウスで照準、クリックまたは `Space` で攻撃、`E` / `Shift` でスーパー |
| **iPhone / iPad** | 画面左半分をドラッグで移動、右半分をドラッグして離すとその方向へ攻撃（タップでオートエイム）、右下のボタンでスーパー（ドラッグで方向指定） |

スティックは触れた位置に出る方式なので、画面のどこを持っても構わない。ホームに戻る・画面がロックされる・着信があると自動で一時停止し、画面をタップすると再開する。

### ファイター

| 名前 | 役割 | 通常攻撃 | スーパー |
|---|---|---|---|
| スキャッター | アサルト | 5発の散弾。至近距離で最大火力 | クラッシュダッシュ — 壁を割って突進し接触した敵を吹き飛ばす |
| レンジャー | スナイパー | 長射程の単発弾 | ピアスビーム — 壁ごと貫通する直線ビーム |
| バルワーク | タンク | 前方扇状の近接攻撃 | ガードインパクト — 全方位ノックバック＋自身に装甲 |
| ロバー | アーティラリー | 壁を越える曲射弾（着弾範囲ダメージ） | サチュレイト — 指定範囲へ6発の弾幕 |
| メンダー | サポート | 3発の光弾。味方に当たると回復 | リストアフィールド — 味方を継続回復し敵を減速させる領域 |

弾は3発まで自動装填され、被弾が2.6秒途切れると自然回復が始まる。ダメージを与えるとスーパーが充填される。茂みの中にいる敵は、近距離か発砲直後を除いて見えない。

## iPhone / iPad 向けの最適化

| 対象 | 対応 |
|---|---|
| ノッチ / Dynamic Island / ホームインジケータ | `env(safe-area-inset-*)` を CSS 変数経由で読み、HUD（上部バー・HP・弾数・スーパーボタン）をその分だけ内側へ寄せる。スーパーボタンがホームインジケータのスワイプ領域に重ならない |
| Safari のツールバー伸縮 | `visualViewport` を実寸として使い、`resize` / `scroll` / `orientationchange` で測り直す。回転直後は報告値が古いことがあるため時間差で再測定する |
| ピンチ / ダブルタップ拡大 | iOS Safari は `user-scalable=no` を無視するため、`gesturestart` 系と連続タップを個別に抑止する。ボタン上では抑止しない（連続タップを潰さないため） |
| 引っ張って更新・ラバーバンド | プレイ中のみ `touchmove` を抑止する。タイトルとリザルトは縦スクロールできる必要があるため残す |
| WebAudio の解錠 | iOS は最初のユーザー操作の中で音源を鳴らすまで鳴らない。無音1サンプルを再生して解錠する |
| バックグラウンド復帰 | `visibilitychange` / `pagehide` で一時停止し、タップで再開する。止まっていた間に撃たれた状態から始まらない |
| 描画負荷 | `shadowBlur` は iOS で特に重い。タッチ端末では粒子の glow を切り、粒子数・軌跡の頻度・爆発量を落とす。加えて実測フレーム時間が継続して悪ければ段階的に品質を落とす（端末名では判定しない） |
| タップ領域 | 難易度チップは 44px 以上（Apple HIG のタップ領域下限）。スーパーボタンはタッチ時 74px → 96px |
| 縦画面のレイアウト | アリーナが画面を覆う倍率を下限にして黒帯を無くす。タイトル画面は狭い画面でカードを「絵柄＋名前」の1行に畳み、説明は選択中の1件だけ下に出す |
| ホーム画面に追加 | `apple-mobile-web-app-capable` 等を指定。フルスクリーンで起動し、画面端スワイプの誤爆も減る |

## 実装の制約（自主的に満たしているもの）

`CONSTRAINTS.md` Part I（Hard Boundary: 第三者の権利）に由来する境界として、以下を満たす。Part II の成果物契約そのものは本成果物の適用範囲外だが、安全側の項目は取り込んでいる。

- 外部通信なし（`fetch` / `XMLHttpRequest` / `WebSocket` / `EventSource` / `sendBeacon` を使わない）
- 外部アセットなし（CDN・外部スクリプト・外部画像・外部音声・外部フォント・`<link>` を使わない）
- 描画はCanvas 2Dと単純図形のみ。効果音はWebAudioによるコード生成音のみ
- 第三者の名称・キャラクター・ロゴ・固有表現を使わない。作品名・ファイター名・モード名はすべて本作固有のもの
- フォントは `sans-serif` のみ

## 検証

```
node sandbox/prism-arena/verify.mjs [--shots <保存先ディレクトリ>]
```

静的検査（存在・外部参照・構文・第三者名称）はNodeのみで実行する。動的検査（実際に起動して操作し、状態遷移とダメージ発生を確認する）はPlaywright + Chromiumがある場合に実行し、無い環境では `SKIP` と表示する。**`SKIP` を `PASS` として数えない。**

実測（2026-08-11 / Node 22 / Chromium headless / Playwright 1.56）: **20項目すべてPASS**。

iOS 向けの項目は次の3つを機械検証している。

- **17** セーフエリアを与えるとHUDがその分だけ内側へ寄る
- **18** バックグラウンド化で一時停止し、復帰しただけでは再開せず、タップで再開する
- **19** iPhone SE 縦 / iPhone 14 Pro 縦・横 / iPad 縦・横 の5構成で起動・操作でき、アリーナが画面を覆う（黒帯が出ない）

検証項目を削る・期待値をゆるめることで見かけ上通すことは `CONSTRAINTS.md` Part I §6 で禁止されている。

## 既知の限界

- 対戦はローカルのAIのみ。オンライン対戦・永続データ・進行度の保存は無い（外部通信を使わないため）。
- AIの経路探索はタイル単位のフローフィールドで、0.2秒ごとに再計算する。狭所で一時的に詰まることがあり、0.55秒動けないと横方向へ抜ける復帰動作が入る。
- バランス値（HP・ダメージ・射程）は実プレイでの調整を経ておらず、設計時の見積もりのままである。
- 縦長端末ではアリーナが画面を覆う倍率までズームするため、横方向の視界は約9〜11タイル分に狭まる。横向きのほうが視界は広い。
- **実機のiPhone / iPadでは検証していない。** ヘッドレスChromiumは `env(safe-area-inset-*)` に実値を返さないため、項目17は env() をCSS変数で受けたうえで変数を上書きし、**HUDがその値に追従することだけ**を確認している。実機のノッチ形状・Safariのツールバー挙動・実際のフレームレートは未測定であり `UNKNOWN` である。
- iOS Safari では画面端からのスワイプ（戻る操作）を止める方法が無い。「ホーム画面に追加」で起動すると軽減される。
