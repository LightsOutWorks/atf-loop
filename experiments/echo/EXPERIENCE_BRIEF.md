## 0. なぜこの文書が存在するか

Round 1のchampion `echo-v1.html` は、Machine Evaluationの全項目（Build健全性 / 操作性 / 意図したMechanicの発現）を通過したうえで、**Human Taste Gateで REJECT された**。判定と反証の記録は `LEARNING.md` §11。

> **Technical Prototypeとしては成功。GameとしてはREJECT。**

反証されたのは実装ではなく、**「機械が全部通れば、それは遊べるゲームである」という評価基準そのもの**である（`OS.md` §12 No Teacher）。本文書は、その評価基準を置き換えるためにHumanが与えたTasteの記述である。

**維持するもの**: Machine Evaluationで確認した **「Hookが機構として成立している」は維持する。** 反証されたのはHookの成立ではなく、その周りの体験である。

## 1. Human verbatim / 実測されたReality（FACT）

Round 1 championを、Human本人が初見・説明なしで実際に遊んだ結果。**この節は解釈せずそのまま保存する。**

> **「びっくりするほどつまらなかった」**

- 選択肢が極端で自由度がない
- ほぼすべてテキストベース
- キャラクターにほとんど動きがない
- 音がない
- 選択肢を選んで最後にテキストを見るだけ
- 育ててもキャラクター自体が大きく変化している感じがない
- キャラクターがかわいくなく、愛着が湧かない

**今回FIXする最重要のHuman Taste**:

> **「育成ゲームでは、育てる対象そのものを好きになれることが必須条件」**

**キャラクター実装への名指しの指摘**:

> 現在の**中央の目のようなECHO**は、機能上の **state visualization** にはなっているが、**「触りたい」「かわいい」「こいつを育てたい」という感情を起こせていない。**

| 誰が | 何を持つ |
|---|---|
| **Human** | **Desire + Taste** |

## 3. Experience Brief（Human verbatim）

### 3-1. 最初に感じたいこと

ゲームを開いた瞬間、**「何こいつ、かわいい。触ってみたい」**と思いたい。

育成ゲームなので、**キャラクターそのものへの愛着を最重要条件**にする。

> **抽象的な記号や目だけではなく、表情・身体・仕草によって感情を読み取りたくなるキャラクターにする。**
> **既存キャラクターのコピーはせず、独自キャラクターにする。**

### 3-2. 最初の10秒

説明文を読ませるのではなく、**ECHOが画面内で勝手に動いている。**

playerが **触る / 撫でる / つつく / ドラッグする** などを試すと、すぐ反応する。

> **入力 → animation + expression + sound が即座に返ること。**

### 3-3. Core Experience

「文章の選択肢を選ぶ」のではなく、**ECHOと直接触れ合う。**

例えば — **撫でる / 遊ぶ / 食べ物を与える / 呼ぶ / 放っておく / 邪魔する / 助ける / 自由にさせる**

具体的なmechanicはAI側でWorld Priorを調べて探索する。

> **ただし、3択の文章を延々選ぶ形式は禁止。**

### 3-4. 育っている感覚

数字を見せて `autonomy +2` のように理解させるのではない。playerが **「あれ？こいつ前とちょっと違う」** と**行動から気付く**ゲームにしたい。

接し方によって次が変わってほしい:

**表情 / animation / playerとの距離 / 好き嫌い / 行動頻度 / 鳴き声・声 / 色や身体的特徴 / 自発行動**

### 3-5. 自由度

「優しくする / 冷たくする」のような**極端な善悪二択にしない。**

> **playerが普通に遊んだ結果として性格が形成されること。性格診断の質問票にはしない。**

### 3-6. Surprise

ECHOはplayerの命令を待つだけの存在にしない。ときどき勝手に —

**何かを見つける / 遊び始める / いたずらする / 怒る / 甘える / 無視する / playerが予想しない反応をする**

> **「こいつ生きてるな」と感じる瞬間が欲しい。**

### 3-7. 音

**無音は禁止。** BGMを大量に作る必要はない。ただし少なくとも次にfeedback soundが欲しい:

**触った音 / 喜び / 嫌がる / 移動 / 発見 / 重要イベント**

> **音もキャラクター性の一部にする。**

### 3-8. 最後

**十分にECHOと関わった後だけ**、playerがECHOへ重要なお願いをする。

その時には **「今まで育ててきたこいつなら、どうするんだろう」** と本気で気になっていたい。

ECHOは、それまでに形成された**性格・playerとの関係・経験**から自分で判断する。結果を見て **「ああ、俺がこう接してきたからか」** と感じたい。

## 4. Player SHOULD FEEL

| いつ | 何を |
|---|---|
| **0秒** | 「何これ、かわいい」 |
| **10秒** | 「触ったら反応した」 |
| **30秒** | 「色々やってみたい」 |
| **数分** | 「ちょっとこいつ好きになってきた」 |
| **中盤** | 「俺の接し方で性格変わってない？」 |
| **終盤** | 「こいつならどうする？」 |
| **Ending** | 「うわ、俺がこう育てた結果だ」 |

## 5. Player SHOULD NOT FEEL

- 「文章を読んでいるだけ」
- 「性格診断を受けている」
- 「正解の選択肢を当てている」
- 「ただの分岐ノベル」
- 「数字を育てている」
- 「何をしても同じ」
- 「キャラクターに興味が持てない」
- 「AIだからすごいと言われているだけ」

## 6. 制作手順の拘束（Human裁定）

> **`大量Concept → 少数Prototype → Human Taste → 深く作る`**

1. **ここからいきなり実装しない。**
2. まずこのBriefから、**ECHOというキャラクター自体の方向性を5案程度**と、**Core Interaction / Core Loop候補を5〜10案**、World Priorを使って探索する。
3. **Human Tasteに関わるため、AIだけで1案へ確定しない。**
4. Character direction と Core Experience の候補をHumanへ見せ、**そこでHuman Taste Gateを通す。**
5. その後、**選ばれた方向についてAIが大量variationを探索する。** 最初から100個の完成ゲームを作る必要はない。

**今回はここ（キャラクター案とCore Experience案を出したところ）で一度停止する。**

**やらないこと**: `echo-v1.html` の小手先のRound 2 patch / v1のDistribution（CrazyGames等）/ dashboard / Platform / analytics / scheduler。

**目的はただ一つ** — **「ヒロ本人が本当に遊びたいECHO」の方向性を、Human Desire + Human Tasteから決めること。**

探索の出力は `REDESIGN_CANDIDATES.md`。
