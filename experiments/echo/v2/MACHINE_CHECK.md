## 検出した欠陥と、その修正（隠さない）

本検査で見つかったのは**製品の欠陥3件と、評価器・生成系自身の欠陥3件**である。

**製品側**

1. **呼んでも数学的に絶対に来なかった。** 初期 trust=0 / indep=0 では判定式が常に負になり、`L-2 呼ぶ` が起動直後には成立しない状態だった。判定を純関数へ切り出して軸ごとに走査した時点で発覚。式を修正。
2. **最後のお願いの `go` 分岐が、遅い個体で完了しなかった。** 完了条件を「状態開始から1400ms」にしていたため、移動の遅いビルドでは到着前に条件が過ぎていた。**到着してからの経過**を起点に変更。
3. **育つと目的地へ永久に到達できなくなった。** 体は接し方に応じて大きくなる（`bodyR()` が 76 → 93）。お願いの目的地を画面幅の固定比（`W*0.14` = 55px）で置いていたため、**壁との衝突で止まる位置（x = bodyR = 93）が目的地より内側になり、到達判定が一生成立しない**。4ビルド中1本でだけ発現した。目的地を体格から算出するよう変更。**「育つと壊れる」種類の欠陥は、育っていない状態のテストでは絶対に見つからない。**

**評価器・生成系側**

4. **置換が黙って適用されていなかった（2件）。** 生成スクリプトの `str.replace` が対象と一致せず、`onDown` の変更が4ビルドとも入らないまま生成されていた。もう1件は**別ファイルに対して置換をかけていた**（`fit()` は core1 にあるのに core2 を書き換えていた）ため、地面の高さ変更が入っていなかった。**Round 1 Learning 4「差分を作った」と「差分が入った」は別 と同型の再発。** 以後、全置換に適用検証（`assert`）を入れた。
5. **評価器が画面寸法を決め打ちしていた。** ボールの座標を計算で求めていたが係数が実際と違い（0.715 と仮定・実際は 0.78）、「地面のボールを掴めない」と**誤って報告していた**。製品は正常だった。実測値参照へ修正。
6. **「放っておくと完遂するか」を観測できていなかった。** 完遂の直後に次の自発行動が始まるため `idle` 状態を捉えられず、常に不成立と出ていた。ログで判定するよう修正。

**評価器側3件のうち2件は、機械が「壊れている」と誤って報告した側の誤りである。** 機械の判定を、確かめずに事実として扱わない。

## 補足 — 挙動差分の読み方（過大評価しないために）

- **指を押さえ続けた時の距離**は、押さえた点がECHOの体の上だったかどうかで大きく変わる。A（ばね）が最小なのは**体を掴むと指へ追従する設計だから**であって、「Aが最も懐いている」ことではない。
- **無操作時の自発移動量**は、その30秒にどの自発行動が抽選されたかで決まる（`sleepy` なら0に近く、`fetch` なら大きい）。**個体の活発さの指標として読まない。**
- **声の基音**は設定値であり、実際にどう聞こえるかは判定していない。

**4本が別物であることは確認した。どれが良いかは判定していない。**
