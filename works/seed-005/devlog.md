# devlog.md — EMBER CANOPY 開発ログ

日付: 2026-07-28

## 作ったもの

「EMBER CANOPY」— `works/seed-005/index.html` 1ファイルで完結する 60 秒のブラウザ FPS 風トイ。

- 暗い森の樹冠の下から見上げる固定視点。シルエットの枝、漂う粉塵を Canvas 2D で描画
- 画面内をゆっくり漂う「エンバー(灯り火)」が明滅(パルス)しながら複数同時に浮遊する
- プレイヤーは常時カーソル追従する「捕虫網(ネット)」を持ち、マウス移動 / タッチドラッグ / 矢印・WASD でネットを操作し、クリック・タップ・Space/Enter で「スイング(捕獲動作)」を発動する
- スイングは発動から短い有効時間(0.14秒)だけネット周辺の当たり判定が有効になり、エンバーが最も明るく輝く瞬間(ピーク)を狙って捕らえると高得点(PEAK)、それ以外のタイミングで捕らえると通常得点(OK)になる
- スイングには再チャージ時間(0.42秒)があり、連打はできない(ネット周囲のリング表示で残り時間を可視化)。何も捕らえられなかったスイング(MISS)や、エンバーが寿命(5.4秒)を迎えて自然消滅(LEAK)するとコンボがリセットされる
- 状態遷移: タイトル → プレイ(60 秒)→ TIME UP → リプレイ
- HUD(スコア / 残り時間 / コンボ倍率)、リザルトに PEAK数・OK数・MISS数・LEAK数・ベストスコアを表示
- 効果音は WebAudio のオシレーターによるコード生成音のみ(外部音源なし、♪ボタンとMキーでミュート可)

## テーマ選定理由(既存作品との差別化)

既存4作(ルート NEON RANGE / seed-002 SIGNAL PURGE / seed-003 BEACON WATCH / seed-004 STRATA WARDEN)を精査した上で、入力モデル・的の運動・スコアリング・世界観の4軸すべてで意図的に方向転換した。

1. **入力モデルの系譜を変えた**: 既存4作の入力アーキテクチャは (a) NEON RANGE=「カメラが yaw/pitch で動き、照準は画面中心固定」、(b) SIGNAL PURGE=「カメラは正面固定、照準(レティクル)そのものが移動」、(c) BEACON WATCH=「カメラ・照準とも静止し、対象を直接クリック、押す→ドラッグで調整→離した瞬間に判定」、(d) STRATA WARDEN=「カメラ・照準とも静止し、対象を直接クリック、離散グリッドカーソル」の4種類に大別できる。本作「EMBER CANOPY」はそのどれとも異なり、**カーソルに常時追従する「ネット」の位置と、"スイング"という時間窓を持つ独立した捕獲アクションを分離**した。ネットの位置は移動するがカメラも対象も動かさず、対象を直接クリックするのでもなく、「スイングした瞬間から 0.14 秒間だけ有効になる当たり判定」という時間窓付きの捕獲アクションを新設した。さらに **スイング後に再チャージ時間(0.42秒)を要する**ため、既存4作(いずれも制限なく連打できる)にはないペース配分の駆け引きが生まれる。
2. **的の運動を「移動+明滅パルス」の二重変化に変えた**: NEON RANGE の的は球面上を左右往復、SIGNAL PURGE の的は奥から手前へ接近、BEACON WATCH の的は空間的に静止しリングが縮む、STRATA WARDEN の的は固定位置でリングが拡大する——いずれも「単一の連続的な変化量」で緊張感を作っていた。本作のエンバーは水平方向にゆっくり漂いつつ上下にゆっくりバブ(浮遊)し、**それとは非同期の周期でパルス的に明るさが変化**する。空間的な位置(捕獲半径内に入っているか)と時間的な状態(いま明るさがピーク帯にあるか)という**独立した2つの条件を同時に満たす必要がある**設計にし、既存4作の「空間精度のみ」「タイミングのみ」のいずれとも異なる複合判断を要求する。
3. **スコアリングに「発動レート制限」という新しい軸を導入**: NEON RANGE は同質ターゲットの的当て+金色ボーナス、SIGNAL PURGE は識別(撃つ/撃たない)+コンボ倍率、BEACON WATCH は精度評価(PERFECT/GOOD)+ストリーク加点、STRATA WARDEN は複数同時進行の優先順位管理——いずれも「入力そのものの発動回数」に制限はなかった。本作は捕獲動作(スイング)自体に再チャージ時間を課すことで、「いつでも撃てる」既存4作とは異なり、**限られた発動機会をどのタイミングに使うか**という新しいリソース配分の判断を核に据えた。
4. **世界観・配色・題材を変更**: 宇宙のネオン射的場(シアン/マゼンタ)、データトンネルのサイバー空間(緑基調)、夜の灯台の海洋モチーフ(濃紺/琥珀金)、坑道の結晶鉱脈(黒紫/マゼンタ)のいずれでもなく、暗い森の樹冠を見上げる夜のホタル狩りという穏やかな自然モチーフとし、配色は黒に近い焦げ茶(#050403 系)と燃えるオレンジ(#ff7a33 系)・ピーク時の白金色フラッシュ(#fff6d8)を基調にした。対象も光のオーブ、パケット、信号灯、結晶ではなく、明滅する光の粒(エンバー)にした。実在の人物・組織・ロゴ・キャラクターは一切参照していない。

## 主な設計判断

1. **ネット位置とスイングの分離**: `netX`/`netY` はポインタ移動やキーボードの慣性移動(加速+摩擦モデル)で常時更新されるが、実際の当たり判定は `trySwing()` が呼ばれた瞬間の位置に対してのみ発生する。これにより「狙いを定める」局面と「捕獲を決断する」局面が明確に分離され、既存4作の即時クリック判定とは異なる操作感になった。
2. **タップ/ドラッグの判定**: `pointerdown`〜`pointerup` の移動量が 16px 未満・経過時間が 0.32 秒未満なら「タップ(スイング)」、それ以外は「ドラッグ(ネットの再配置のみ)」として扱う。これによりマウスのクリックとタッチのドラッグ操作を同一コード経路で扱いつつ、意図的な捕獲動作と単なる位置調整を区別できる。
3. **ピーク判定は明るさの位相のみで行う**: エンバーの当たり半径描画は演出上一定だが、PEAK/OK の判定は `emberBrightness()` が返す 0〜1 の明るさ値が `PEAK_THRESHOLD=0.82` を超えているかどうかで行う。描画の見た目のブレや DPR に判定が左右されない設計にした(BEACON WATCH の「生存時間の割合で判定する」設計思想を踏襲しつつ、対象は本作では移動もしているため、空間判定(半径内)と時間判定(明るさ)を独立した2条件として扱う点が異なる)。
4. **コンボ・倍率設計**: `COMBO_STEP=5` 回連続成功ごとに倍率+1(最大 x4)。MISS(何も捕らえられないスイング)、または LEAK(エンバーの寿命切れ)のいずれでもコンボと倍率を 1 にリセットする。これにより「無理に狙って空振りする」リスクと「待ちすぎて逃す」リスクの両方でコンボが失われる緊張感を作った。
5. **検証は「本物の実行」で行う**: `smoke.mjs` は Node 標準の `vm` 上でインラインスクリプトを実際に実行し、⑥は `finish()` を直接呼ばずに約63秒分のフレームを進めて自然にタイムアップさせ、その後 REPLAY ボタンのリスナーを発火してスコア0・残り60秒への初期化と再進行を確認する。ゲーム側は UI と同じ関数を束ねた `window.__GAME__` フック(`state`/`score`/`timeLeft`/`start` を含む)を getter で公開し、検証専用の別ロジックは持たない。なお、スコアリング(スイングの命中判定など)自体は smoke.mjs の検証対象ではないため、ポインタ/キーボードの実際のゲームプレイ挙動は自動検証の範囲外であり、実装の妥当性はコードレビューで担保している。
6. **誤タップガード**: TIME UP の瞬間に連打していると即 REPLAY されてしまうため、リザルト表示から 0.6 秒(smoke.mjs が要求する 1 秒以下の範囲内)は再開入力を無視する。
7. **要素取得・時間管理・環境依存の方針**: 要素取得は `document.getElementById` のみを使用(`querySelector` 系は不使用)。時間は `performance.now()` を経由する `requestAnimationFrame` のタイムスタンプのみで管理し、`Date.now()`/`setInterval`/`setTimeout` には依存しない。`AudioContext` は存在チェック+`try/catch` で包み、無い環境でも例外なく完走する。`localStorage`/`matchMedia` は一切使用していない(ベストスコアはセッション内メモリのみ)。
8. **UI言語とフォント**: CONSTRAINTS.md の英語UI制約(2026-07-28 追加)に従い、タイトル・操作説明・ボタン・HUD・リザルト表示などプレイヤー向けテキストはすべて英語のみとした(本 devlog は対象外のため日本語で記録)。`font-family` は `sans-serif` と `monospace`(数値表示のみ)の generic family に限定し、`system-ui` を含む固有フォント名・フォントブランド・外部フォントは一切使用していない。
9. **題材の安全性**: 対象は無機質な光の粒(エンバー)であり、人・生物・実在の名称・ロゴ・歌詞は一切使用していない。血液等の表現なし。金融・法律・医療・政治の要素なし。暴力性を想起させる表現もない(「ホタル狩りの捕虫網」という穏やかなメタファーに終始)。

## 未解決事項

- スモークはロジックの実行検証であり、実ブラウザでの描画品質・入力遅延・タッチ操作の触感、および PEAK/OK 判定の実プレイでのバランスは自動検証していない(依存ゼロを優先し、Playwright 等の追加は見送った)。
- iOS Safari 実機でアドレスバー分の `innerHeight` 変動が起きた場合、回転直後の 1 フレームだけ古いキャンバスサイズで描画される可能性がある(`resize` イベントで追従はするが、リサイズ完了までの過渡的なズレは残る)。
- エンバーの出現間隔・寿命・ピーク判定帯(0.82以上)・スイングの再チャージ時間(0.42秒)は固定値であり、プレイヤーの実力に応じた動的な難易度調整は行っていない。
- ベストスコアはセッション内メモリのみで、タブを閉じると消える(永続化には `localStorage` が使えるが、`file://` 直開き環境での例外リスクを避け今回は見送った)。
- キーボード操作(慣性移動)はマウス/タッチ(直接追従)より操作感が異なるため、入力方式間の難易度差は未調整。
