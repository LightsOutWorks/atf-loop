# devlog.md — VOLT CACHE 開発ログ

日付: 2026-08-01

## 作ったもの

「VOLT CACHE」— `works/seed-008/index.html` 1ファイルで完結する 60 秒のブラウザ FPS 風トイ。

- 夜の屋上変電所を正面から見た固定視点。都市の灯りのボケ、送電アンテナのシルエット、時折の稲光を Canvas 2D で描画
- 画面内をゆっくり漂う2種類のターゲットが同時に複数出現する: 「セル」(小さな光の粒、常に破壊可能)と「ヴォールト」(大きな封印カプセル、破壊にはバンクした CHARGE が必要)
- セルを破壊すると加点+ CHARGE を1貯蓄。ヴォールトは表示されたコスト分の CHARGE が貯まっていれば破壊でき大きく加点、コストが足りないまま挑むと「NEED n MORE」表示とともに失敗し、ストリークがリセットされる(ヴォールト自体は消えず再挑戦できる)
- ターゲットには寿命があり、時間切れで放置(LEAK)すると同様にストリークがリセットされる
- 操作はマウス/タップでの直接クリック、キーボードは左右(または A/D)でターゲットを選択し Enter/Space で確定する離散選択方式
- 状態遷移: タイトル → プレイ(60 秒)→ GRID SECURED → リプレイ
- HUD(スコア / 残り時間 / CHARGE / コンボ倍率)、リザルトに CELLS数・VAULTS数・DENIED数・LEAKS数・ベストスコアを表示
- 効果音は WebAudio のオシレーターによるコード生成音のみ(外部音源なし、♪ボタンとMキーでミュート可)

## テーマ選定理由(既存作品との差別化)

ATF IDEA FUNNEL v1 の手順に従い、まず works/ 配下の既存7作(seed-001〜seed-007)のコアメカニクスを一行でメモした:

- seed-001 NEON RANGE: カメラが yaw/pitch で回転し、照準は画面中心に固定。的は球面上を往復。瞬間ヒット判定。
- seed-002 SIGNAL PURGE: カメラ固定、照準(レティクル)が2次元移動。的は奥から手前へ接近。撃つ/撃たないの識別+コンボ倍率。
- seed-003 BEACON WATCH: カメラ・対象とも静止、対象を直接クリック。押す→ドラッグ→離した瞬間の縮小リングでタイミング判定(PERFECT/GOOD)。
- seed-004 STRATA WARDEN: 固定6スロットが同時多発的に暴走。拡大するリングの安定帯でタイミング判定。複数同時管理。
- seed-005 EMBER CANOPY: カーソル追従のネット+独立した「スイング」アクション(有効窓+再チャージ)。空間条件と明滅位相の二重条件判定。
- seed-006 FROST HARPOON: 銛が一定速度で飛翔し貫通ヒット。1発で複数体を巻き込むチェインボーナス。固定ピボットの1次元回転照準。
- seed-007 METEOR CHARGE: 1次元の並進スライダー。押しっぱなしチャージ→離した瞬間の充填率で威力ティア決定、対象の耐性と比較(撃破/ひび割れ/見逃し)。

この7作はいずれも「入力(クリック/タップ/確定操作)の瞬間、または飛翔終了時に成否が一度で決まる」判定と、「その場限りの得点計算」という構造を共有していた。VOLT CACHE ではこの構造を崩すため、**プレイ全体を通して持ち越される「CHARGE(通貨)」という永続リソース**を導入し、以下の点で意図的に方向転換した。

1. **判定を「1回の入力」から「積み上げた資源の有無」に変えた**: 既存7作はいずれも、成否がその1回の入力(角度・タイミング・威力など)だけで決まった。本作のヴォールト判定は、**過去に何回セルを割ったか(=現在の CHARGE 残高)** に依存する。同じ入力(クリック)でも、それ以前のプレイヤーの行動history によって成否が変わる、既存7作にない「状態の持ち越し」を核にした。
2. **「無理な早撃ちはコンボを失うだけで対象は残る」という新しいペナルティ構造**: STRATA WARDEN の TOO EARLY やSIGNAL PURGE の誤射はいずれも対象を消費するか得点を減らす方向のペナルティだったが、本作の DENIED(charge不足での挑戦)は**対象を破壊せずそのまま残す**。プレイヤーは「今は無理でも後で CHARGE が貯まれば再挑戦できる」ため、"あきらめて温存する" か "無理に試して手がかりを得る"かという既存作にない資源管理の駆け引きが生まれる。
3. **敵味方識別(SIGNAL PURGE)や複数同時管理(STRATA WARDEN)とは異なる軸**: SIGNAL PURGE は「見た瞬間に正しい/誤りを判断する」識別ゲームだったが、本作の2種のターゲット(セル/ヴォールト)は最初から見分けやすく(形状が違う)、識別自体は易しい。難しいのは識別ではなく「今のCHARGE残高でヴォールトに挑めるか」という**自分の内部状態を参照する判断**である点が質的に異なる。
4. **世界観・配色・題材を変更**: 宇宙のネオン射的場、データトンネル、夜の灯台、坑道の結晶鉱脈、暗い森の樹冠、氷洞の見張り砲台、砂漠の観測ドームのいずれでもなく、**夜の屋上変電所で漂う電荷を回収し、封印カプセルを解錠する**というモチーフとし、配色は深い藍黒(#060a10系)とシアン(#8fe3ff系)・紫のヴォールト(#c9b6ff系)を基調にした。対象も光のオーブ・パケット・信号灯・結晶・エンバー・蒸気の光点・隕石ではなく、幾何学的な光の粒(セル)と六角形の封印カプセル(ヴォールト)にした。実在の人物・組織・ロゴ・キャラクター・地名は一切参照していない。

## 主な設計判断

1. **CHARGE はセッション内の永続状態として一元管理**: `currency` 変数をプレイ開始時に 0 にリセットし、セル破壊で+1、ヴォールト成功で `-cost` する以外に変動させない。ヴォールトの `cost` は固定値(`VAULT_COST=5`)とし、画面上に常時 `⚡cost` を表示することで、プレイヤーが挑戦可否を毎回自分で判断できるようにした(隠しパラメータにしない)。
2. **DENIED は対象を消費しない設計**: `resolveHit()` でヴォールトの charge が不足する場合、`targets` 配列から要素を削除せず、`deniedUntil` によって短時間だけ赤い警告フラッシュを出すだけにとどめた。これにより「時間切れ寸前でもまだ CHARGE が足りないヴォールトを見送り、セルを稼いでから戻ってくる」という行動が成立する。
3. **寿命(LEAK)による見逃しペナルティは既存作の踏襲だが判定には使わない**: ターゲットには `life` による自然消滅を設けてストリークをリセットする(既存作と同様の"取りこぼしリスク")が、これは CHARGE の有無とは独立した軸であり、本作の核心である資源管理判断とは別レイヤーの緊張感として重ねた。
4. **入力は直接クリック+離散キーボード選択**: 本作の新規性はターゲットの狙い方ではなく資源判断にあるため、狙い方自体は既存作(BEACON WATCH/STRATA WARDEN)で実証済みの「対象を直接クリック/タップ」+「矢印・ADで選択、Enter/Spaceで確定」という手堅い方式を採用し、実装・検証の安定性(C4)を優先した。
5. **検証は「本物の実行」で行う**: `smoke.mjs` は Node 標準の `vm` 上でインラインスクリプトを実際に実行し、⑥は `finish()` を直接呼ばずに約63秒分のフレームを進めて自然にタイムアップさせ、その後 REPLAY ボタンのリスナーを発火してスコア0・残り60秒への初期化と再進行を確認する。ゲーム側は UI と同じ関数を束ねた `window.__GAME__` フック(`state`/`score`/`timeLeft`/`start` を含む)を getter で公開し、検証専用の別ロジックは持たない。
6. **誤タップガード**: GRID SECURED の瞬間に連打していると即 REPLAY されてしまうため、リザルト表示から 0.6 秒(smoke.mjs が要求する 1 秒以下の範囲内)は再開入力を無視する。
7. **要素取得・時間管理・環境依存の方針**: 要素取得は `document.getElementById` のみを使用(`querySelector` 系は不使用)。時間は `performance.now()` を経由する `requestAnimationFrame` のタイムスタンプのみで管理し、`Date.now()`/`setInterval`/`setTimeout` には依存しない。演出上の稲光フラッシュも `tNow` の三角関数のみで駆動し、実時刻・乱数シードには依存しない。`AudioContext` は存在チェック+`try/catch` で包み、無い環境でも例外なく完走する。`localStorage`/`matchMedia` は一切使用していない(ベストスコアはセッション内メモリのみ)。
8. **UI言語とフォント**: CONSTRAINTS.md の英語UI制約に従い、タイトル・操作説明・ボタン・HUD・リザルト表示などプレイヤー向けテキストはすべて英語のみとした(本 devlog は対象外のため日本語で記録)。`font-family` は `sans-serif` と `monospace`(数値・CHARGE表示のみ)の generic family に限定し、`system-ui` を含む固有フォント名・フォントブランド・外部フォントは一切使用していない。
9. **題材の安全性**: 対象は無機質な光の粒(セル)と幾何学的な封印カプセル(ヴォールト)であり、人・生物・実在の名称・ロゴ・歌詞は一切使用していない。血液等の表現なし。金融・法律・医療・政治の要素なし(「CHARGE」はゲーム内の抽象リソースであり、実在通貨・決済を想起させる表現は用いていない)。暴力性を想起させる表現もない(「変電所の電荷を回収し封印カプセルを解錠する」という保全・解錠のメタファーに終始する)。

## 未解決事項

- スモークはロジックの実行検証であり、実ブラウザでの描画品質・入力遅延・タッチ操作の触感、および CHARGE 経済(コスト5・セル1個あたり+1)の実プレイでのバランスは自動検証していない(依存ゼロを優先し、Playwright 等の追加は見送った)。
- iOS Safari 実機でアドレスバー分の `innerHeight` 変動が起きた場合、回転直後の 1 フレームだけ古いキャンバスサイズで描画される可能性がある(`resize` イベントで追従はするが、リサイズ完了までの過渡的なズレは残る)。
- ヴォールト出現確率(`pVault`)・寿命・CHARGE コスト(固定5)は固定値であり、プレイヤーの実力や CHARGE 残高に応じた動的な難易度調整は行っていない。
- ベストスコアはセッション内メモリのみで、タブを閉じると消える(永続化には `localStorage` が使えるが、`file://` 直開き環境での例外リスクを避け今回は見送った)。
- ヴォールトが複数同時に画面上に残った状態でまとめて CHARGE を貯めてから連続で解錠する「溜め撃ち」戦略が理論上可能だが、そのペース配分の最適解は未検証。
