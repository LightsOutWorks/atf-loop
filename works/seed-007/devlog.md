# devlog.md — METEOR CHARGE 開発ログ

日付: 2026-08-01

## 作ったもの

「METEOR CHARGE」— `works/seed-007/index.html` 1ファイルで完結する 60 秒のブラウザ FPS 風トイ。

- 砂漠の天文観測ドームを見上げる固定視点。夜空(星の瞬き)・砂丘のシルエットを Canvas 2D で描画
- 画面下部を左右にスライドする「充填式キャノン(charge cannon)」を、マウス移動/タッチドラッグ/矢印・ADキーで水平方向のみ操作する(回転もカメラ移動もなし)
- 発射はクリック/タップ/Space・Enterの「押しっぱなしでチャージ→離した瞬間に発射」方式。チャージ時間の長さで威力(I/II/III の3段階)が決まり、離した瞬間の充填率で自動判定される
- 上空から S(小)/M(中)/L(大) の3種類の隕石が落下してくる。威力が対象の耐性以上なら撃破、不足していると**破壊されずワンランク小さい隕石にひび割れて縮小するだけ**(貫通も瞬間ヒットもしない、1発=1標的の単発判定)
- 隕石を撃ち漏らして地表(ドーム基部)に到達させると BREACH としてコンボがリセットされる
- 状態遷移: タイトル → プレイ(60 秒)→ SKY CLEARED → リプレイ
- HUD(スコア / 残り時間 / コンボ倍率)、リザルトに DESTROYED数・CRACKED数・BREACH数・ベストスコアを表示
- 効果音は WebAudio のオシレーターによるコード生成音のみ(外部音源なし、♪ボタンとMキーでミュート可)

## テーマ選定理由(既存作品との差別化)

既存6作(ルート NEON RANGE / seed-002 SIGNAL PURGE / seed-003 BEACON WATCH / seed-004 STRATA WARDEN / seed-005 EMBER CANOPY / seed-006 FROST HARPOON)を精査した上で、入力モデル・判定モデル・世界観の3軸すべてで意図的に方向転換した。

1. **入力自由度を「1次元の水平移動」にした**: 既存6作の操作対象は (a) NEON RANGE=カメラの yaw/pitch 回転、(b) SIGNAL PURGE=2次元移動する照準、(c) BEACON WATCH=2次元ドラッグ、(d) STRATA WARDEN=2次元グリッドカーソル、(e) EMBER CANOPY=2次元の慣性移動するネット、(f) FROST HARPOON=固定ピボットからの1次元「回転」——のいずれかだった。本作は自機(キャノン)を画面下部のレール上で**左右にスライドさせるだけの1次元「並進」**とし、回転操作は一切ない。FROST HARPOON と同じ「1次元入力」という制約は踏襲しつつ、その中身を回転から並進に変えることで操作感を明確に変えた(マウスは絶対X座標に追従する"スライダー"、タッチはドラッグ、キーボードは矢印/ADで一定速度移動)。
2. **判定モデルを「押しっぱなしチャージ→離した瞬間の充填率で威力決定」に変えた**: NEON RANGE/SIGNAL PURGE/STRATA WARDEN/FROST HARPOON は入力の瞬間(またはその後の飛翔終了時)に成否が決まる方式で、威力という概念自体が存在しない。BEACON WATCH は「押す→ドラッグで狙いを調整→離した瞬間に対象の縮小リングと照合して判定」だったが、これは**対象側の状態(リング半径)** を判定基準にしていた。本作は対象の状態を一切見ず、**プレイヤー自身の入力継続時間(チャージ量)** だけで威力ティア(I/II/III)を決め、その威力と対象の耐性を比較して結果を出す。「狙いを直す」ためのドラッグではなく「威力を溜める」ためのホールドである点が BEACON WATCH とは根本的に異なる。
3. **「撃破 or 見逃し」の二択から「撃破・ひび割れ(部分成功)・見逃し」の三択に拡張**: STRATA WARDEN は安定帯判定で4段階の結果を作ったが、対象は毎回消滅する前提だった。本作は威力不足のヒットで対象を**消さずに弱化させるだけ**(L→M→S)という「命中はしたが決着しない」状態を導入し、同じ対象に対して複数回・複数ティアの判断を重ねる余地を作った(FROST HARPOON の「1発で複数体を貫通する」拡張とは逆方向に、「1体に対して複数発を要することがある」という縮小方向の拡張)。
4. **世界観・配色・題材を変更**: 宇宙のネオン射的場(シアン/マゼンタ)、データトンネルのサイバー空間(緑基調)、夜の灯台の海洋モチーフ(濃紺/琥珀金)、坑道の結晶鉱脈(黒紫/マゼンタ)、暗い森の樹冠(焦げ茶/オレンジ)、氷洞の見張り砲台(藍黒/氷シアン)のいずれでもなく、**砂漠の天文観測ドームが夜空から降る隕石群を迎撃する**というモチーフとし、配色は夜空の藍紫(#0d0714〜#241533系)と砂丘の琥珀・アンバー(#3a2418 / #c98a4b / #ffcf8a系)、隕石の燃えるオレンジ(#ff8a3d系)を基調にした。対象も光のオーブ・パケット・信号灯・結晶・エンバー・蒸気の光点ではなく、大きさの異なる隕石の幾何学的な円にした。実在の人物・組織・ロゴ・キャラクター・地名は一切参照していない(「dune」等の特定作品を想起させる語も避け、タイトル・本文では使用していない)。

## 主な設計判断

1. **並進のみの1次元操作モデル**: `turretX` のみを状態として持ち、`turretY` はプレイ開始時に固定値(`H - TURRET_Y_OFFSET`)へ設定する。マウス/タッチは `pointermove` でキャンバス座標系のX値に直接追従させる「スライダー」方式にし、キーボードは `TURRET_KEY_SPEED` による等速移動とした。狙いの自由度を意図的に1軸へ絞ることで、既存6作の中で最も単純な移動入力にし、代わりにチャージ判断へプレイヤーの注意を向けさせる設計にした。
2. **チャージ量→威力ティアの変換**: `charge = min(1, (tNow - chargeStart) / CHARGE_FULL_TIME)` を0〜1の連続値とし、離した瞬間に `TIER1_MAX=0.34` / `TIER2_MAX=0.74` の閾値でI/II/IIIの3段階に離散化する。チャージ中も移動・キャンセル(`pointercancel`)が可能で、`pointercancel` 時は発射せずに単にチャージを破棄する(誤操作で暴発しない)。
3. **威力と耐性の比較による三分岐**: 隕石は `{S:耐性1, M:耐性2, L:耐性3}` を持ち、命中したショットの `tier >= req` なら撃破(得点+コンボ加算)、`tier < req` ならワンランク小さい種別へ弱化するだけでコンボは変化させない(「無理に強打を溜めず、当てられる分だけ小さくしていく」戦略も許容するため)。1発のショットは1体にしか当たらない単発判定とし、FROST HARPOON の貫通(1発=複数体)とは対称的な「1発=最大1体」のシンプルな衝突方式にした。
4. **発射後のクールダウンで連射を抑制**: `FIRE_COOLDOWN=0.15秒` の間は次のチャージを開始できない。チャージ自体に最短でも入力継続が必要なため実質的な連射制限にはなるが、チャージ0(即離し=ティアI)の連打を完全に防ぐための下限として設定した。
5. **見逃し(BREACH)によるコンボリセット**: 隕石が `breachY()`(ドーム基部の高さ)へ到達すると強制的に撃破・弱化を経ずに消滅し、コンボと倍率をリセットする。撃破の代わりに軽い画面シェイク演出(`shakeUntil`)を入れて視覚的なペナルティを与えた。
6. **難易度カーブ**: 経過時間 `elapsed / GAME_TIME` に応じて L・M の出現確率を線形に増加させ(`pL`・`pM`)、出現間隔も終盤ほど短くする。STRATA WARDEN の「同時暴走数の増加」とは異なる軸(個体の出現頻度・大型化)で終盤の負荷を上げる設計にした。
7. **検証は「本物の実行」で行う**: `smoke.mjs` は Node 標準の `vm` 上でインラインスクリプトを実際に実行し、⑥は `finish()` を直接呼ばずに約63秒分のフレームを進めて自然にタイムアップさせ、その後 REPLAY ボタンのリスナーを発火してスコア0・残り60秒への初期化と再進行を確認する。ゲーム側は UI と同じ関数を束ねた `window.__GAME__` フック(`state`/`score`/`timeLeft`/`start` を含む)を getter で公開し、検証専用の別ロジックは持たない。なお、隕石の耐性判定・チャージ量とティアの対応など実際のゲームプレイ挙動自体は smoke.mjs の検証対象ではなく、実装の妥当性はコードレビューで担保している。
8. **誤タップガード**: SKY CLEARED の瞬間に連打していると即 REPLAY されてしまうため、リザルト表示から 0.6 秒(smoke.mjs が要求する 1 秒以下の範囲内)は再開入力を無視する。
9. **要素取得・時間管理・環境依存の方針**: 要素取得は `document.getElementById` のみを使用(`querySelector` 系は不使用)。時間は `requestAnimationFrame` が渡すタイムスタンプ(ms→秒変換)のみで管理し、`Date.now()`/`setInterval`/`setTimeout` には依存しない。`AudioContext` は存在チェック+`try/catch` で包み、無い環境でも例外なく完走する。`localStorage`/`matchMedia` は一切使用していない(ベストスコアはセッション内メモリのみ)。
10. **UI言語とフォント**: CONSTRAINTS.md の英語UI制約に従い、タイトル・操作説明・ボタン・HUD・リザルト表示などプレイヤー向けテキストはすべて英語のみとした(本 devlog は対象外のため日本語で記録)。`font-family` は `sans-serif` と `monospace`(数値表示のみ)の generic family に限定し、`system-ui` を含む固有フォント名・フォントブランド・外部フォントは一切使用していない。
11. **題材の安全性**: 対象は無機質な隕石(幾何学的な円)であり、人・生物・実在の名称・ロゴ・歌詞は一切使用していない。血液等の表現なし。金融・法律・医療・政治の要素なし。暴力性を想起させる表現もない(「観測ドームを隕石群から守る迎撃」という穏やかな防衛・観測のメタファーに終始する)。

## 未解決事項

- スモークはロジックの実行検証であり、実ブラウザでの描画品質・入力遅延・タッチ操作の触感、およびチャージ量とティア判定の実プレイでのバランス(閾値0.34/0.74が適切か)は自動検証していない(依存ゼロを優先し、Playwright 等の追加は見送った)。
- iOS Safari 実機でアドレスバー分の `innerHeight` 変動が起きた場合、回転直後の 1 フレームだけ古いキャンバスサイズで描画される可能性がある(`resize` イベントで追従はするが、リサイズ完了までの過渡的なズレは残る)。
- 隕石の出現確率カーブ(`pL`/`pM` の線形増加)・チャージ時間(0.72秒)・クールダウン(0.15秒)は固定値であり、プレイヤーの実力に応じた動的な難易度調整は行っていない。
- ベストスコアはセッション内メモリのみで、タブを閉じると消える(永続化には `localStorage` が使えるが、`file://` 直開き環境での例外リスクを避け今回は見送った)。
- 画面幅が極端に狭い場合、`TURRET_MARGIN=42` によりキャノンの可動範囲が視覚的なドーム幅に対して相対的に狭くなる可能性があり、超小型ビューポートでの操作感は未検証。
