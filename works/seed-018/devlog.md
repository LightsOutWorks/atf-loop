# devlog — seed-018

## 作品名
GATE SHIFT

## テーマ選定理由(既存作品との差別化)
準備段階で works/ 配下の既存17作品(seed-001〜017)を一行棚卸しした結果、コアメカニクスは概ね次の系統に集約された。

- 直接照準+発射・識別射撃(seed-001/002/006/012)
- ホールド/ドラッグ→リリースで単一対象に対するタイミング合わせ(seed-003/004/005/007/009/016)
- タップ即分裂・階層ポップ、バンク管理からの割高消費(seed-008/010)
- 単一の全域トグル(seed-011: タップするたびフィールド全体の磁極を反転)
- 落下物の積み上げ・二択ルーティング・シーソー балансировка(seed-014/015)
- 3ゾーンの独立ホールド管理(seed-013)
- 連続ドラッグによる間接・角度制御(seed-017)

これらは「対象へ直接・離散的に作用する入力」か「プレイヤー自身のタップで即座に切り替わる単一トグル」のどちらかに大別できた。GATE SHIFT はこのどちらとも異なり、**判定基準(ゲート側の受理色)が時間経過で自動的に、かつプレイヤーの操作とは無関係に再配置され続ける**点を核に据えた。プレイヤーは「対象をどう狙うか」ではなく「今この瞬間、正解のマッピングは何か」を読み取ってから3レーンのどのゲートを叩くかを決める。seed-002(SIGNAL PURGE)の識別式タップとは、ルールが固定か周期的に変化するかで区別され、seed-011(MAGNET TIDE)の全域トグルとは、切替がプレイヤーのタップ由来かゲーム側のタイマー由来かで区別される。

フェーズ1で出した12候補のうち、"QUOTA STACK"(納品先クォータが周期的に変わる荷物仕分け)は GATE SHIFT と同一の「周期的に変わるルールに基づく分類」が核であったため統合し、GATE SHIFT 側の表現を残した。"GATE ROUTER"(パドルを連続ドラッグして落下物を複数ビンへ振り分ける)も、入力方式こそ連続ドラッグだが「対象を正しい出力先に割り当てる」という決定構造が GATE SHIFT と同一であったため統合した。同様に "LATTICE GROWTH"(ノードを設置してネットワークを育てつつ隣接ハザードの拡散を防ぐ)は "CLAIM FRONTIER"(タイルを確保してハザードの拡散を食い止める)とコアメカニクスが同一(確保拡大 vs 拡散ハザード)と判断し、より実装が単純な CLAIM FRONTIER 側の表現に統合した。残った9候補をフェーズ3で採点した結果、GATE SHIFT と PULSE ECHO(記憶シーケンス再現)が同点最高(26点)、SPARK CHAIN(連鎖反応の着火)が僅差の25点で続いた。

GATE SHIFT を最終選定した理由は、C1(既存作品との違い)と C3(操作・決定の独自性)で PULSE ECHO を上回った点にある。PULSE ECHO の「順序記憶→再現」自体は既知のトイパターンで題材差し替えに留まりやすいのに対し、GATE SHIFT の「対象の色」「レーンの位置」「ゲートが今受理している色」という3つの独立した状態を毎回突き合わせて判断する決定は、既存作品のどの系統にも見られない。また C7(習熟後の新戦略の出現)は、ゲートの受理色が約6〜8.5秒ごとに強制的に再配置されるため、プレイヤーがどれだけ習熟してもマッピングを一度覚えて終わりにはならず、終盤ほど「シフト直後は様子を見るか、勘で叩くか」という新しい判断が生まれる設計にした。SPARK CHAIN は C7 で並んだが、連鎖反応の是非を60秒以内の数手で学ばせる調整(C4/C5)の実装難易度が高く、次点に留めた。詳細な採点は funnel.json を参照。

## 主な設計判断
- **判定はゲート側、対象側ではない**: タップ対象を「落下するグリフそのもの」ではなく「レーン下部の大きなゲート領域」にした。これにより (a) プレイヤーの決定が「このグリフを狙って叩く」ではなく「今このレーンのゲートは何色を受理しているか」を読んでから叩くという、ラベル読解込みの判断になる、(b) 当たり判定面積が広く安定し、狭い1点を正確に狙う操作精度への依存を避けられる、という2つの効果を狙った。
- **ゲート受理色は毎回異なる配置へ**: `shuffleGates()` は直前の配置と完全一致する順列を避けて再抽選する。単純にランダムだと稀に「見た目上は変化したが実質同じ配置」になり得るため、これを明示的に排除して「シフトのたびに必ず学び直しが必要」という体験を保証した。
- **ミスの非対称な扱い**: 誤った色のグリフをゲートで捕まえるとスコア減点+コンボリセットを即座に行うが、正解のはずのグリフをゲートで捕まえ損ねて画面外に流した場合はコンボリセットのみで減点はしない。「疑わしきは見送る」より「疑わしくても叩きに行く」方をわずかに得にすることで、受動的なプレイに倒れないようにした。
- **success_condition の設計**: `checkSuccess` は `catchCount >= 1` を返す。これは `catchLane()` 内で、あるレーンのゲート領域に実際にグリフが存在した状態でタップが解決された場合にのみインクリメントされる実カウンタで、正誤を問わない。meta.json の primary_input は `tap` であり、その1回の実行が引き起こす最小の観測可能な状態変化(グリフが1つ消え、スコアかコンボのいずれかが変化し、ゲートにフラッシュが入る)を指しており、「3連続正解」のような複合達成条件にはしていない。
- **キーボード対応**: マウス/タッチのポインタ操作に加え、Left/Right で選択レーンを移動、Enter/Space で選択中のゲートを叩く操作を実装し、PCキーボードのみでも完結できるようにした。
