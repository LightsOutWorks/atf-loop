# devlog.md — STRATA WARDEN 開発ログ

日付: 2026-07-28

## 作ったもの

「STRATA WARDEN」— `works/seed-004/index.html` 1ファイルで完結する 60 秒のブラウザ FPS 風トイ。

- 坑道の岩壁を正面から見た固定視点。ひび割れた岩肌と浮遊する粉塵を Canvas 2D で描画
- 岩壁には 3×2 = 6 個の結晶脈スロットが固定位置に配置され、そのうち数個がランダムなタイミングで「暴走」を始める
- 暴走中の結晶脈は時間とともにエネルギー(輪の半径)が 0→最大まで拡大し続け、輪が**安定帯(点線で示された内側〜外側リングの間)**に達した瞬間にクリック/タップして鎮めると STABLE、安定帯に届く前に触れると空振り(TOO EARLY)、安定帯を過ぎても最大まで拡大しきる前に鎮めれば弱めの STRAINED、放置して最大まで拡大させると RUPTURE(コンテインメント失敗)としてストリークが 0 にリセットされる
- 操作は「暴走中の結晶脈を直接クリック/タップする」即時判定方式(マウス/タッチ共通)。キーボードは矢印/WASD でグリッド上のカーソルを 2 次元的に移動し、Space/Enter で鎮める離散選択方式
- 状態遷移: タイトル → プレイ(60 秒)→ CONTAINMENT COMPLETE → リプレイ
- HUD(スコア / 残り時間 / ストリーク)、リザルトに STABLE数・STRAINED数・空振り数・RUPTURE数・最大ストリークを表示
- 効果音は WebAudio のオシレーターによるコード生成音のみ(外部音源なし、♪ボタンでミュート可)

## テーマ選定理由(既存作品との差別化)

既存3作(NEON RANGE / SIGNAL PURGE / BEACON WATCH)を精査した上で、以下の軸で意図的に方向転換した。

1. **同時進行(並行性)の導入**: 既存3作はいずれも「常に単一の対象(照準・的・信号灯)を狙う/選ぶ」設計だった(NEON RANGE は同時に複数の的が浮遊するが的当て自体は独立、SIGNAL PURGE は移動する照準ひとつで狙う、BEACON WATCH は選択式で常に1つを確定する)。本作は**複数の結晶脈スロットが同時に暴走し得る**設計にし、プレイヤーは「今どれを優先して鎮めるか」という同時多発的な判断を常に迫られる。単一対象の精度・識別・タイミングではなく、**複数リソースの同時管理**をゲーム性の核にした。
2. **対象の空間的性質を「固定位置・時間で変化」に変えた**: NEON RANGE は的が球面上を移動、SIGNAL PURGE は的が奥から手前へ移動、BEACON WATCH は的が空間的に静止しリングが縮む。本作の結晶脈スロットは**盤面上の位置が完全に固定**(6 個の決まった場所)で、暴走の有無とエネルギー値だけが時間で変化する。これによりキーボード操作を「対象を辿って選ぶ」から「固定グリッド上でカーソルを 2 次元移動する」方式に変更でき、既存3作の 1 次元選択/連続移動とは質的に異なる入力になった。
3. **判定窓を「縮小」から「拡大」に反転**: BEACON WATCH は光が消えるまでの残り時間が少なくなるほど輪が縮む設計だった。本作は逆に、時間とともに輪が拡大し続け、安定帯を通過してもなお拡大し続けて最終的に RUPTURE する設計にした。「早すぎる」「ちょうど良い」「遅すぎるが致命的ではない」「手遅れ」という 4 段階の結果を輪の拡大方向で表現し、視覚的な緊張の作り方を反転させた。
4. **世界観・配色・題材を変更**: 宇宙のネオン射的場(シアン/マゼンタ)、データトンネルのサイバー空間(緑基調)、夜の灯台の海洋モチーフ(濃紺/琥珀)のいずれでもなく、坑道内の結晶鉱脈という地下モチーフとし、配色は黒に近い紫(#0a0613 系)と紫水晶のマゼンタ(#d68cff 系)・警告のオレンジ/レッド(#ffb454 / #ff5470 系)を基調にした。対象も光の的やパケット、信号灯ではなく、岩壁に埋め込まれた結晶(ジャギーな多角形)にした。実在の人物・組織・ロゴ・キャラクターは一切参照していない。

## 主な設計判断

1. **固定グリッド + 同時複数暴走モデル**: スロットは `slotPos(i)` で盤面座標を固定的に算出し、`slots[i]` に暴走中の結晶脈情報(発生時刻)を保持する配列とした。同時に暴走できる最大数は経過時間に応じて 1→2→3 と増加させ、終盤ほど同時に複数を捌く必要がある難易度カーブにした。
2. **拡大するエネルギーで 4 段階の結果を表現**: `energyOf(v) = (tNow - bornT) / VEIN_LIFE` を 0〜1 の進行度とし、`BAND_START=0.55` 〜 `BAND_END=0.82` を安定帯とした。安定帯前に触れると空振り(TOO EARLY)、安定帯内で STABLE(コンボに応じて加点、コンボ継続)、安定帯を過ぎても 1.0 未満なら STRAINED(固定 4 点、コンボはリセット)、1.0 に達すると自動で RUPTURE(コンボリセット+画面シェイク)とした。STRAINED でもコンボをリセットすることで、「安定帯を逃したら無理に粘らず次に備える」か「粘って弱くても回収するか」という選択の緊張感を作った。
3. **クリック位置からのスロット特定**: `slotAt(px, py)` で最も近い(かつヒット半径 + 余白以内の)スロットを求めて `tryStabilize` を呼ぶ。マウスのクリックとタッチのタップを同一の `pointerdown` ハンドラで扱い、ドラッグ操作は不要な即時判定にすることで、BEACON WATCH の「押す→ドラッグ→離す」モデルとは異なる入力感触にした。
4. **固定グリッド上のキーボードカーソル**: `moveCursor(dCol, dRow)` は 2 次元グリッド上で行・列を独立に折り返し移動させる。BEACON WATCH の「出現中の的だけを 1 次元的に順送りで選ぶ」方式とは異なり、暴走していないスロットにもカーソルを合わせられる(その場合 Enter/Space で空振り扱いになる)ことで、常に固定の盤面を意識した操作感にした。
5. **検証は「本物の実行」で行う**: `smoke.mjs` は Node 標準の `vm` 上でインラインスクリプトを実際に実行し、⑥は `finish()` を直接呼ばずに約63秒分のフレームを進めて自然にタイムアップさせ、その後 REPLAY ボタンのリスナーを発火してスコア0・残り60秒への初期化と再進行を確認する。ゲーム側は UI と同じ関数を束ねた `window.__GAME__` フック(`state`/`score`/`timeLeft`/`start` を含む)を getter で公開し、検証専用の別ロジックは持たない。
6. **誤タップガード**: CONTAINMENT COMPLETE の瞬間に連打していると即 REPLAY されてしまうため、リザルト表示から 0.6 秒(smoke.mjs が要求する 1 秒以下の範囲内)は再開入力を無視する。
7. **要素取得・時間管理・環境依存の方針**: 要素取得は `document.getElementById` のみを使用(`querySelector` 系は不使用)。時間は `performance.now()` を経由する `requestAnimationFrame` のタイムスタンプのみで管理し、`Date.now()`/`setInterval`/`setTimeout` には依存しない。`AudioContext` は存在チェック+`try/catch` で包み、無い環境でも例外なく完走する。`localStorage`/`matchMedia` は一切使用していない(ベストスコアはセッション内メモリのみ)。
8. **題材の安全性**: 対象は無機質な結晶(幾何学的な多角形)であり、人・生物・実在の名称・ロゴ・歌詞は一切使用していない。血液等の表現なし。金融・法律・医療・政治の要素なし。暴力性を想起させる表現もない(「暴走前に鉱脈を鎮める」という抽象的な管理・メンテナンスのメタファーに終始)。

## 未解決事項

- スモークはロジックの実行検証であり、実ブラウザでの描画品質・入力遅延・タッチ操作の触感は自動検証していない(依存ゼロを優先し、Playwright 等の追加は見送った)。
- iOS Safari 実機でアドレスバー分の `innerHeight` 変動が起きた場合、回転直後の 1 フレームだけ古いキャンバスサイズで描画される可能性がある(`resize` イベントで追従はするが、リサイズ完了までの過渡的なズレは残る)。
- 同時暴走数(1→2→3)・出現間隔・安定帯の範囲(0.55〜0.82)は固定値であり、プレイヤーの実力に応じた動的な難易度調整は行っていない。
- ベストスコアはセッション内メモリのみで、タブを閉じると消える(永続化には `localStorage` が使えるが、`file://` 直開き環境での例外リスクを避け今回は見送った)。
- 6 スロット全てが同時に暴走候補になり得る配置だが、視覚的な密集(3×2グリッドの中央付近)によりごく小さな画面幅では隣接スロットのヒット判定余白(`HIT_PAD`)が重なる可能性があり、極端に狭いビューポートでの誤タップ率は未検証。
