# devlog.md — BEACON WATCH 開発ログ

日付: 2026-07-28

## 作ったもの

「BEACON WATCH」— `works/seed-003/index.html` 1ファイルで完結する 60 秒のブラウザ FPS 風トイ。

- 夜の海に浮かぶ灯台からの一人称視点。回転するビーム(装飾のみ・スコアに無関係)、星空、波打ち際を Canvas 2D で描画
- 沖に不定期で現れる「信号灯(flare)」が、輪(リング)を縮めながら短時間だけ光る
- 狙いは「輪が最も小さくすぼまる一瞬」に捉えると PERFECT、それ以外のタイミングで捉えても GOOD。光が消えるまで放置すると連続記録(ストリーク)が途切れる
- 操作は「押す→ドラッグで狙いを調整→指/ボタンを離した瞬間に判定」という統一入力(マウスもタッチも同じロジック)。キーボードは矢印/AD/WS で信号灯を選択し、Space/Enter で確定する選択式入力
- 状態遷移: タイトル → プレイ(60 秒)→ WATCH COMPLETE → リプレイ
- HUD(スコア / 残り時間 / ストリーク)、リザルトに PERFECT数・GOOD数・空振り数・見逃し数を表示
- 効果音は WebAudio のオシレーターによるコード生成音のみ(外部音源なし、♪ボタンでミュート可)

## テーマ選定理由(既存作品との差別化)

既存2作を精査した上で、以下の3軸すべてで意図的に方向転換した。

1. **入力モデルの系譜を変えた**: ルートの「NEON RANGE」は"カメラ(視点)が yaw/pitch で動き、照準は画面中心に固定"。「SIGNAL PURGE」は"カメラは正面固定、照準そのものが画面内を移動する"。本作「BEACON WATCH」はどちらでもなく、**カメラ・照準ともに移動させず、対象そのものを直接クリック/タップする一発判定方式**を採る。さらにマウス/タッチは「押す→ドラッグで狙いを微調整→離した瞬間に判定」という統一ロジックにし、キーボードは「対象を Tab 送りのように選択してから確定する」という、既存2作(連続的な視点/照準移動)とは質的に異なる離散選択方式にした。
2. **的の運動を"移動"から"時間経過による変化(パルス)"に変えた**: NEON RANGE の的は球面上を左右に往復し、SIGNAL PURGE の的は奥(Z軸)から手前へ接近する——どちらも空間内を移動する的を"追う/狙う"ゲーム性。本作の信号灯は**空間的には静止**し、代わりに出現から消滅までの間にリング半径が時間とともに縮む。プレイヤーが克服すべき軸は「空間的な照準精度」ではなく「時間的な判断(いつ捉えるか)」であり、既存2作の"追跡"型から"タイミング"型へゲーム性を移した。
3. **敵味方識別から離れ、単一対象の精度評価に変えた**: SIGNAL PURGE は「撃つべきバグ」と「誤射してはいけない正常パケット」の識別が核だった。本作は対象は信号灯 1 種類のみで、誤って別対象を撃つ、というペナルティは存在しない。代わりに「同じ対象をどれだけ良いタイミングで捉えられたか」という精度評価(PERFECT/GOOD)で得点差をつけ、識別ゲームとは異なる緊張感を作った。
4. **世界観・配色・題材を変更**: 宇宙のネオン射的場(シアン/マゼンタ)、データトンネルのサイバー空間(緑基調+走査線)のいずれでもなく、夜の灯台から沖を見張るという穏やかな海洋モチーフとし、配色は濃紺(#050b1a 系)と琥珀・金色(#ffd27a 系)を基調にした。対象も球体の的やブロック状の敵ではなく、光るリングの信号灯という抽象表現にした。実在の人物・組織・ロゴ・キャラクターは一切参照していない。

## 主な設計判断

1. **押下→ドラッグ→離す、で統一した入力**: `pointerdown` で狙い位置を記録し、`pointermove` で(押していてもいなくても)狙いを追随させ、`pointerup` で最終位置に対して判定する設計にした。これによりマウスのクリック(ほぼ同時刻の down/up)とタッチのドラッグ操作(down→複数回の move→up)を同一コード経路で扱え、タップ/ドラッグ双方に自然に対応する。キーボードは連続移動ではなく `moveSelection`/`confirmSelected` による離散選択+確定とし、対象が空間移動しないゲーム性に合わせた。
2. **時間ベースの判定窓**: 信号灯の生存時間 `FLARE_LIFE=1.55s` に対し、経過割合が `CORE_START=0.42〜CORE_END=0.78` の間に捕捉すると PERFECT、それ以外の生存中なら GOOD、生存時間を過ぎると自動消滅して「見逃し」としてストリークをリセットする。半径 `flareRadius()` は見た目上の縮小演出であり、実際の当たり判定は生存時間の割合(`flareFrac`)で行うことで、描画パフォーマンスや DPR に判定がぶれない設計にした。
3. **ストリーク加点方式**: SIGNAL PURGE の「5コンボごとに倍率が上がる乗算式」とは変え、`bonus = min(5, floor(streak/3))` を基礎点に**加算**するボーナス方式にした。連続成功で徐々に上乗せされるが、乗算のように得点が急伸しない緩やかな成長曲線を意図した。
4. **検証は「本物の実行」で行う**: `smoke.mjs` は Node 標準の `vm` 上でインラインスクリプトを実際に実行し、⑥は `finish()` を直接呼ばずに約63秒分のフレームを進めて自然にタイムアップさせ、その後 REPLAY ボタンのリスナーを発火してスコア0・残り60秒への初期化と再進行を確認する。ゲーム側は UI と同じ関数を束ねた `window.__GAME__` フック(`state`/`score`/`timeLeft`/`start`)を getter で公開し、検証専用の別ロジックは持たない。
5. **誤タップガード**: WATCH COMPLETE の瞬間に連打していると即 REPLAY されてしまうため、リザルト表示から 0.6 秒(smoke.mjs が要求する 1 秒以下の範囲内)は再開入力を無視する。
6. **要素取得・時間管理・環境依存の方針**: 要素取得は `document.getElementById` のみを使用(`querySelector` 系は不使用)。時間は `performance.now()` を経由する `requestAnimationFrame` のタイムスタンプのみで管理し、`Date.now()`/`setInterval`/`setTimeout` には依存しない。`AudioContext` は存在チェック+`try/catch` で包み、無い環境でも例外なく完走する。`localStorage`/`matchMedia` は一切使用していない(ベストスコアはセッション内メモリのみ)。
7. **題材の安全性**: 対象は無機質な光のリング(信号灯)であり、人・生物・実在の名称・ロゴ・歌詞は一切使用していない。血液等の表現なし。金融・法律・医療・政治の要素なし。暴力性を想起させる表現もない(「灯台からの見張り」という穏やかなメタファーに終始)。

## 未解決事項

- スモークはロジックの実行検証であり、実ブラウザでの描画品質・入力遅延・ドラッグ操作の触感は自動検証していない(依存ゼロを優先し、Playwright 等の追加は見送った)。
- iOS Safari 実機でアドレスバー分の `innerHeight` 変動が起きた場合、回転直後の 1 フレームだけ古いキャンバスサイズで描画される可能性がある(`resize` イベントで追従はするが、リサイズ完了までの過渡的なズレは残る)。
- 信号灯の出現間隔・同時出現数は時間経過に応じた固定カーブであり、プレイヤーの実力に応じた動的な難易度調整は行っていない。
- ベストスコアはセッション内メモリのみで、タブを閉じると消える(永続化には `localStorage` が使えるが、`file://` 直開き環境での例外リスクを避け今回は見送った)。
- PERFECT/GOOD の判定窓(0.42〜0.78)は仮の値であり、実プレイでの難易度バランス調整の余地がある。
