## 設計の出所（Humanの音声メモ）

Humanが口頭で述べた要素を、そのまま実装対象とした。

| 述べられたこと | 実装 |
|---|---|
| 「顔先に紫にして、でどんどん青く緑になって」 | ゾンビの顔色をHP比で連続変化させる。色相 = `130 + 比率 × 150` → 満タン**紫280** / 半分**青205** / 瀕死**緑130**。体力バーは出さず、色だけで残量を読ませる |
| 「ゾンビを倒すと宝箱が出て」 | 撃破時に宝箱をドロップ（通常13%、ブルートは確定、22体撃破ごとに確定） |
| 「それをゲットするとくじがしてる」 | 宝箱に触れると「くじ」+1 |
| 「くじを引くとルーレットに回って…アイテムがもらえます」 | くじ1枚消費 → 8分割ルーレットが回転（easeOutCubic、4〜6周）→ 停止した出目のアイテムを獲得 |
| 「ゾンビになった人たちを倒して何分か耐えます」 | 生存時間 **180秒（3分）**。耐えきれば `SURVIVED`、体力0で `OVERRUN` |
| 「タワーディフェンスみたいな感じ」 | 全方位から寄せてくる群れをさばくサバイバー型。攻撃は自動、プレイヤーは位置取りだけを操作する |

## 主な設計判断

- **攻撃を自動にした。** 3分間スマホで手動照準を続けるのは苦行になる。プレイヤーの意思決定を
  「どこに立つか」「くじをいつ引くか」の2つに絞ることで、群れをさばく判断がゲームの中身になる。
- **ルーレット中はゲームを止めた**（`state` は `play` のまま、`roul.active` で制御）。
  当たりを見る時間を作らないと、報酬が報酬として成立しない。
- **ルーレットの出目名は盤と一緒に回さず、常に水平に描いている。**
  盤と一緒に回すと左半分が上下逆さまになり読めなかった（実際に発生させて修正した）。
- **8つの出目のうち7つは永続強化、1つ（衝撃波）は即時効果**だが、衝撃波にも回復15を付けて
  「ハズレを引いた」感触が出ないようにした。
- 状態遷移・`__GAME__` フック・`performance.now()` 基準の時間管理・単一ファイル構成・外部参照ゼロは、
  既存の `works/seed-*` の実装作法をそのまま踏襲した（`CONSTRAINTS.md` Part II を品質バーとして流用）。
  ただし Part II は seed ルート専用の契約であり、本作はその適用対象ではない。

### 2. `verify-browser.mjs`（実ブラウザでの通し検証）— 34/34 PASS

実 Chromium 上で `index.html` を実際に動かし、時間だけを固定クロックに置き換えて
`requestAnimationFrame` を手動で回す。ゲーム側の判定ロジックには一切手を入れていない。

```
node verify-browser.mjs ./index.html    # 要 playwright（リポジトリの依存には加えていない）
```

通っている項目:

- 初期状態 `title` / 開始で `play` / 残り180秒 / スコア・くじ0 / 体力満タン
- ゾンビが出現し、自動攻撃で撃破でき、スコアが増える
- **色相の端点が 紫280 → 青205 → 緑130**、満タンは紫域、被弾済みは色相が下がる
- 宝箱を拾うとくじが増える（かつ、その時点で生存している＝到達可能な導線である）
- くじを引くとルーレットが始まり、くじを1枚消費し、**その間ゲーム時間が止まる**
- ルーレットが停止して出目が確定し、**能力値または体力が実際に変わる**
- ルーレットが閉じてゲームが再開し、時間が進む
- **時間切れまで耐えると生還する**（`cleared=true` / 残り0秒 / 体力残あり）
- **体力0になると敗北する**（`cleared=false` / 体力0 / 時間は残っている）
- 再プレイで 時間・スコア・撃破数・くじ・体力・**強化内容**・ゾンビ・宝箱がすべて初期化される
- キーボード（D）で移動する
- ページ内で例外が出ない / `console.error` が出ない

```

run 4: 生還 180s 撃破281 / run 5: 死亡  59s 撃破33  / run 6: 死亡 120s 撃破87
```
