# devlog.md — PRISM SPLIT 開発ログ

日付: 2026-08-02

## 作品名

PRISM SPLIT — `works/seed-010/index.html` 1ファイルで完結する 60 秒のブラウザ FPS 風トイ。

## テーマ選定理由(既存作品との差別化)

準備段階で works/seed-001〜009 のコアメカニクスを一行でメモした:

- seed-001 NEON RANGE: カメラが yaw/pitch で回転、照準は画面中心固定。的は球面上を往復。瞬間ヒット判定。
- seed-002 SIGNAL PURGE: カメラ固定、照準が2次元移動。的は奥から手前へ接近。撃つ/撃たないの識別+コンボ倍率。
- seed-003 BEACON WATCH: カメラ・対象とも静止、対象を直接クリック。押す→ドラッグ→離した瞬間の縮小リングでタイミング判定。
- seed-004 STRATA WARDEN: 固定6スロットが同時多発的に暴走。拡大するリングの安定帯でタイミング判定。複数同時管理。
- seed-005 EMBER CANOPY: カーソル追従のネット+独立した「スイング」アクション(有効窓+再チャージ)。空間条件と明滅位相の二重条件判定。
- seed-006 FROST HARPOON: 銛が一定速度で飛翔し貫通ヒット。1発で複数体を巻き込むチェインボーナス。固定ピボットの1次元回転照準。
- seed-007 METEOR CHARGE: 1次元の並進スライダー。押しっぱなしチャージ→離した瞬間の充填率で威力ティア決定、対象の耐性と比較。
- seed-008 VOLT CACHE: プレイ全体を通して持ち越される CHARGE(永続通貨)。バンク→解錠のコスト判断。
- seed-009 TETHER LOCK: 押し続けて対象をロックする持続コミット型判定。乗り換えで進捗が失われる。

この9作はいずれも「1回の入力(またはその後の飛翔・保持の完了)で成否が確定し、対象は消えるか消えないかのどちらか」という構造を共有していた。対象がタップそのものによって**別の対象へ形を変え、盤面のエンティティ構成そのものを書き換える**メカニクスは存在しなかった。PRISM SPLIT ではこの点を核として意図的に方向転換した。

1. **「対象を消す/消さない」から「対象を作り替える」への転換**: 本作のプリズムは3段階のティア(大/中/小)を持ち、大・中をタップすると**消滅せずに2つの小さいプリズムへ分裂する**(得点は小さいが即座に入る)。最小ティアをタップして初めて完全に「ポップ」して大きく得点する。既存9作はいずれもヒットした対象が消えるか、消えず居残るだけ(VOLT CACHE の DENIED)のどちらかで、タップ自体が**新しいエンティティを盤面に追加する**設計は無かった。
2. **決定が後続の盤面構成に直接影響する**: 1個の大プリズムを最後まで分裂させ切ると、都度の分裂ボーナスと最終的な複数回のポップ得点を合計でき、直接ポップより高い期待値になるが、その分エンティティ数が増えて画面が混み合い、寿命切れ(LEAK)によるコンボ崩壊のリスクも増える。「1つを最後まで追い込むか、複数の種火に浅く手を出して分散するか」という、既存作のどれとも異なる資源配分(自分が生み出した対象をどう管理するか)の判断軸を作った。VOLT CACHE の CHARGE は外部通貨だったが、本作では**プレイヤー自身の操作が生み出した対象の個体数そのもの**がリソースになる点が異なる。
3. **入力は最も単純な直接タップに絞った**: 新規性の軸をメカニクス(分裂の連鎖)に置くため、狙い方自体は BEACON WATCH / STRATA WARDEN / VOLT CACHE で実証済みの「対象を直接クリック/タップ」+「矢印・ADで選択、Enter/Spaceで確定」という手堅い方式を採用し、実装・検証の安定性(C4)と学習のしやすさ(C5)を優先した。
4. **世界観・配色・題材を変更**: 宇宙のネオン射的場、データトンネル、夜の灯台、坑道の結晶鉱脈、暗い森の樹冠、氷洞の見張り砲台、砂漠の観測ドーム、屋上変電所、深海のドリフターのいずれでもなく、夕暮れの峡谷を漂う光のプリズムというモチーフとし、配色は夕焼けの藍紫〜琥珀(#180d26〜#5a2f1e系)と、ティアごとに異なる色(大=アンバー #ffb45c、中=マゼンタピンク #ff6fae、小=シアン #7fe9ff)を基調にした。対象も光のオーブ・パケット・信号灯・結晶・エンバー・蒸気の光点・隕石・光の粒・ドリフターではなく、幾何学的な光のプリズム(回転する正方形=菱形)にした。実在の人物・組織・ロゴ・キャラクター・地名は一切参照していない。

## 主な設計判断

1. **3ティアの分裂モデル**: `TIER_R=[34,23,14]` / `TIER_LIFE=[9.2,6.6,4.6]` / `TIER_SPEED=[15,26,40]` とし、ティアが上がる(小さくなる)ほど寿命が短く速度が速くなることで、分裂を重ねるほど盤面の管理難度が上がるようにした。ティア0/1をタップすると `resolvePrism()` が2体の子(ティア+1)を親の速度ベクトルから左右に開いた角度で生成し、`SPLIT_BONUS(5)×combo` を即座に加点する。ティア2(最小)をタップすると `POP_VALUE(16)×combo` を加点して完全に消滅させる。
2. **タップは pointerdown で即時解決**: seed-009 TETHER LOCK の実装では `handleAim()` が `if (!holding) { engagedId = ...; return; }` という条件のせいで、ポインタ操作からは一度もホールドを開始できない欠陥があった(JOURNAL.md 0001)。本作は「押した瞬間に成否が決まる」タップ判定を採用し、`pointerdown` ハンドラが `findPrismAt()` の結果を条件なしに直接 `resolvePrism()` へ渡す一本道の経路にすることで、同種の「実行不可能な入力経路」を作らないようにした。
3. **キーボードは離散選択+確定**: `moveSelect(±1)` で x 座標順にプリズムを巡回選択し、`confirmSelected()` は選択中のプリズム(未選択なら先頭)を `resolvePrism()` に渡す。ポインタのタップと同じ関数を共有するため、入力経路ごとに判定ロジックが分岐しない。
4. **リソースとしてのプリズム個体数**: 新規スポーン(`spawnRandomTier0`)は盤面の総数が `CAP_SPAWN(9)` 未満のときだけ行うが、分裂そのものはこの上限を無視して常に成立させる(プレイヤーの成功行動を上限で拒否しないため)。ティア2の寿命が短いことで、分裂を重ねすぎた盤面は自然に収束する。
5. **Interaction Contract**: タイトル画面は「tap a drifting prism to split it... or tap a fully-split shard to pop it」と約束しているため `primary_input="tap"` とした。`success_condition="prism_resolved_1"` は、タップ1回が引き起こす最小の観測可能な変化(分裂またはポップが1回成立すること)を指す。`checkSuccess()` は入力ハンドラが立てるフラグではなく、実際に `resolvePrism()` が実行されるたびに増える `resolvedCount`(分裂数+ポップ数の実カウント)が1以上かを読んで判定する。
6. **検証は「本物の実行」で行う**: `smoke.mjs` は Node 標準の `vm` 上でインラインスクリプトを実際に実行し、⑥は `finish()` を直接呼ばずに約63秒分のフレームを進めて自然にタイムアップさせ、その後 REPLAY ボタンのリスナーを発火してスコア0・残り60秒への初期化と再進行を確認する。`scripts/interaction-smoke.mjs` は実 Chromium 上で 5×4 のグリッド座標へ実際の `mouse.down/up` を打ち、`window.__GAME__.checkSuccess()` が真になるまで最大25秒試行する。
7. **誤タップガード**: CANYON CLEARED の瞬間に連打していると即 REPLAY されてしまうため、リザルト表示から 0.6 秒(smoke.mjs が要求する 1 秒以下の範囲内)は再開入力を無視する。
8. **要素取得・時間管理・環境依存の方針**: 要素取得は `document.getElementById` のみを使用(`querySelector` 系は不使用)。時間は `requestAnimationFrame` が渡すタイムスタンプ(ms→秒変換)のみで管理し、`Date.now()`/`setInterval`/`setTimeout` には依存しない。`AudioContext` は存在チェック+`try/catch` で包み、無い環境でも例外なく完走する。`localStorage`/`matchMedia` は一切使用していない(ベストスコアはセッション内メモリのみ)。
9. **UI言語とフォント**: CONSTRAINTS.md の英語UI制約に従い、タイトル・操作説明・ボタン・HUD・リザルト表示などプレイヤー向けテキストはすべて英語のみとした(本 devlog は対象外のため日本語で記録)。`font-family` は `sans-serif` と `monospace`(数値表示のみ)の generic family に限定し、`system-ui` を含む固有フォント名・フォントブランド・外部フォントは一切使用していない。
10. **題材の安全性**: 対象は無機質な光のプリズム(幾何学図形)であり、人・生物・実在の名称・ロゴ・歌詞は一切使用していない。血液等の表現なし。金融・法律・医療・政治の要素なし。暴力性を想起させる表現もない(「分裂」「ポップ」はいずれも光の粒が形を変える抽象的な演出であり、破壊や攻撃のメタファーではない)。

## 未解決事項

- スモークはロジックの実行検証であり、実ブラウザでの描画品質・入力遅延・タッチ操作の触感、および分裂連鎖の実プレイでのバランス(SPLIT_BONUS=5 と POP_VALUE=16 の比率が適切か)は自動検証していない(依存ゼロを優先し、Playwright は Interaction Contract の検証にのみ用いている)。
- iOS Safari 実機でアドレスバー分の `innerHeight` 変動が起きた場合、回転直後の 1 フレームだけ古いキャンバスサイズで描画される可能性がある(`resize` イベントで追従はするが、リサイズ完了までの過渡的なズレは残る)。
- プリズムの出現間隔(0.85〜1.5秒)・上限(9個)・ティアごとの寿命/速度は固定値であり、プレイヤーの実力に応じた動的な難易度調整は行っていない。
- ベストスコアはセッション内メモリのみで、タブを閉じると消える(永続化には `localStorage` が使えるが、`file://` 直開き環境での例外リスクを避け今回は見送った)。
- 分裂した2体が同時に画面端付近で生成された場合、跳ね返り処理までの1フレームだけ境界外に一瞬はみ出す可能性があるが、次フレームで即座に補正されるため実害は確認していない。
