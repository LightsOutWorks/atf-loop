# devlog — seed-009

## 作品名
TETHER LOCK

## テーマ選定理由(既存作品との差別化)
works/seed-001〜008 は共通して「単発クリック」または「タイミングが合った瞬間に1回押す」系の判定(即時ヒット、あるいはリング/チャージが目標値に達した瞬間の単発操作)で成立しており、プレイヤーの意思決定は基本的に「いつ・どこを1回押すか」に収斂していた(NEON RANGE・SIGNAL PURGE の単発照準、BEACON WATCH・STRATA WARDEN のリング一致タイミング、EMBER CANOPY の追従キャッチ、FROST HARPOON の貫通ショット、METEOR CHARGE のホールド→解放、VOLT CACHE の通貨バンク→単発クラック)。
TETHER LOCK はこれらと異なり、「ポインタ/キーを押し続けて対象に照準を合わせ続ける」ことで進行する持続コミット型の判定を核に据えた。ロックは時間経過で自動的に閾値へ到達するのではなく、プレイヤーが押し続けている間だけ進行し、押している最中に別対象へ照準が近づくと進捗が失われる「乗り換えコスト」を持つ。これは C1(既存作との違い)を満たすためのメカニクス上の差別化であり、題材(深海のドリフター)は既存の題材(射撃レンジ・データトンネル・灯台・鉱山・森・氷洞・砂漠天文台・屋上変電所)と重複しないよう選んだが、選定の主因はあくまで判定方式の違いである。

## 主な設計判断
- 判定の核を「保持時間で満ちるロックリング」とし、離す/乗り換えると進捗が失われる設計にすることで、C3(操作とプレイヤーの決定の独自性)と C7(慣れた頃の新戦略の余地: 低価値ターゲットの周回か高価値ターゲットへの長時間コミットかの選択)を確保した。
- ターゲットを2種類(glimmer: 低価値・短いロック時間・短命/pulsar: 高価値・長いロック時間・長命)に絞り、プレイヤーの選択(どちらを狙うか、乗り換えるか)がスコアと後続の状況に直接影響する設計にした(「決定が後続状態を変えない」パターンを避けるため)。
- マウス/タッチ/キーボードを同一のホールド操作(pointerdown〜pointerup、touch は pointer イベント経由、Enter/Space の keydown〜keyup)に統一することで C4(実装安定性)と入力方式間の公平性を確保した。
- スモークテスト(smoke.mjs)の仮想 DOM ではポインタ操作やキー操作が実行されないため、ゲームロジックは「無操作のままでも 60 秒間クラッシュせず進行し、タイムアップ後に再プレイでスコア/時間が初期化される」ことを満たすように独立してテストした。
- 効果音は AudioContext の存在チェックと try/catch を通した上でのみ生成し、検証環境(AudioContext 不在)でも例外なく動作するようにした。
