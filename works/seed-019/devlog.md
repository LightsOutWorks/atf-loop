# devlog — seed-019「GRID PATROL」

## 作品名

GRID PATROL

## テーマ選定理由(既存作品との差別化)

ATF IDEA FUNNEL のフェーズ1〜3で候補を12個出し、統合後11個を C1〜C7 で採点した(詳細は `funnel.json`)。
既存18作品(works/seed-001〜018)は「照準して撃つ/リングのタイミングで押す/ホールドしてチャージ・解放/ドラッグで連続的に操作する/ラベルの一致を見て選ぶ」といった、エイム・タイミング・ホールド系のメカニクスに集中していた。

GRID PATROL のコアメカニクスは「昇順に並んだ数字ノードを、見た目や配置の妨害の中から探して順番にタップする」という**視覚探索+順序追跡**であり、この系統の意思決定(次に叩くべき対象を"探す"こと自体が挑戦になる)は既存作品のどれとも重ならない(C1=4)。
次点候補の ECHO CHAIN(連鎖反応の経路選択)や SIGNAL RECALL(順序の記憶再生)も新規性は高かったが、実装の安定性(C4)と数手以内の理解しやすさ(C5)で GRID PATROL に劣ったため、3候補中から GRID PATROL を選定した。

## 主な設計判断

- **座標系をポインタ検証と一致させた**: 盤面を 960×600 のビューポートに対して 5列×4行(セル 192×150px)の固定グリッドで構成し、当たり判定もセル単位(`cellFromPos`)にした。これは `scripts/interaction-smoke.mjs` が実ブラウザで 960×600 のビューポート上を 5×4 グリッドの各セル中心座標を順に叩くことを踏まえた設計で、乱数で生成されるノード配置がどのセルに来ても、セル中心を狙う機械操作で確実にヒットする。
- **「次の数字」だけをハイライトしない**: HUD に NEXT の数字は出すが、盤面側でその数字のノードを光らせるような誘導は入れていない。誘導すると探索の意思決定が消えてただのタイミングゲームに戻ってしまうため。
- **間違えてもノードは消えない**: 誤タップ(順番違いの数字)はコンボをリセットしペナルティを与えるが、ノード自体は残る。プレイヤーが赤いフラッシュを見て「今のは違った」と学習し、すぐ次を狙い直せるようにするため(C6: 即時フィードバック)。
- **ラウンドごとに盤面密度を上げる**: 1〜9 が揃うたびに、次ラウンドは配置数を+1(最大20マス全埋め)して再抽選する。数字を探す難度が上がることで、慣れてきたプレイヤーに「走査パターンを最適化する」という新しい工夫の余地が生まれる(C7)。
- **`checkSuccess` は実際のカウンタを読む**: 正解タップ時にのみ加算される `correctTaps` を参照しており、ハンドラが呼ばれた事実だけを見るフラグにはしていない。

## 未解決事項

- ラウンドが進み盤面が20マス全埋めになった後の難度カーブは頭打ちになる(セル数を超えて増やせないため)。60秒のプレイ時間内では実運用上ほぼ問題にならないと判断し、今回は上限固定のままにした。
- 誤タップのペナルティ量(-5点)とコンボリセットの強さは初期値の勘で決めており、実プレイでの体感バランス調整は行っていない。
