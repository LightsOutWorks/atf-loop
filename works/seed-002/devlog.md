# devlog.md — SIGNAL PURGE 開発ログ

日付: 2026-07-28

## 作ったもの

「SIGNAL PURGE」— `works/seed-002/index.html` 1ファイルで完結する 60 秒のブラウザ FPS 風トイ。

- 固定視点のデータトンネル(同心の枠が中心から手前に流れてくる疑似トンネル演出)を Canvas 2D で描画
- トンネルの奥から「バグ(赤い棘ブロック)」と「正常パケット(青い丸ブロック)」がプレイヤー方向へ接近してくる
- プレイヤーは画面固定のカメラに対して**照準(レティクル)そのものを動かす**(マウス移動 / タップ&ドラッグ / 矢印・WASD)、クリック・タップ・Space/Enter で駆除
- バグを駆除すると加点してコンボが伸び、5 コンボごとに倍率が上昇(最大 x5)。正常パケットを誤射すると減点してコンボが 0 にリセットされる。バグを駆除し損ねて手前を通過させて見逃す(leak)とコンボがリセットされる
- 状態遷移: タイトル → プレイ(60 秒)→ PURGE COMPLETE → リプレイ
- HUD(スコア / 残り時間 / コンボ倍率)、リザルトに駆除数・誤射数・見逃し数を表示
- 効果音は WebAudio のオシレーターによるコード生成のみ(外部音源なし、M キーとボタンでミュート可)

## テーマ選定理由(既存作品との差別化)

ルートの既存作品「NEON RANGE」は、宇宙空間に浮かぶ光のオーブに向けて**カメラ(視点)を yaw/pitch で動かし**、画面中央固定の照準でオーブを撃つ疑似3D射的トイだった(ネオンのシアン/マゼンタ配色、的は静止しつつ左右にゆったり往復するだけ)。

「SIGNAL PURGE」は以下の点で意図的に方向転換した:

1. **視点とカメラの関係を反転**: NEON RANGE は「カメラが動き、照準は画面中心に固定」。本作は「カメラは正面固定、照準(レティクル)そのものが画面内を移動する」設計にし、操作感を明確に変えた。
2. **的の運動軸を変えた**: NEON RANGE の的は一定距離の球面上で左右に往復するだけ。本作の的は**奥(Z軸)から手前へ接近してくる**設計にし、疑似トンネルの奥行き表現と「近づくほど大きく速く見える」緊張感を主軸にした。
3. **単純な的当てから識別シューティングへ**: NEON RANGE はすべての的が「撃てば得点」の同質ターゲット(+金色コアのボーナスのみ)。本作は「撃つべきバグ」と「撃ってはいけない正常パケット」を混在させ、誤射のペナルティとコンボ制を導入することで、判断力と手元の精度が同時に問われるゲーム性にした。
4. **世界観・配色・題材を変更**: 宇宙/ネオンの射的場ではなく、ターミナル/データ配線を思わせる緑基調+走査線オーバーレイのサイバー空間とし、対象も光のオーブではなく幾何学的な「バグ」「パケット」の抽象ブロックにした(実在の人物・組織・ロゴ・キャラクターは一切参照していない)。

## 主な設計判断

1. **固定カメラ + 移動レティクルの入力モデル**: FPS 的な視点操作を毎回同じ実装にしないため、視点(カメラ)は完全固定し、代わりに照準を PC ではマウス絶対位置、スマホではドラッグの相対移動、キーボードでは矢印/WASD の一定速度移動で操作できるようにした。ポインターロックは不使用(権限プロンプト・スマホ非対応・iframe 失敗のリスクを避けるため NEON RANGE と同方針)。
2. **奥行き表現は Z 減少型の単純透視投影**: ワールド座標 (x, y, z) を `screen = center + focal * (x,y) / z` で投影し、z をフレームごとに減算するだけで「奥から手前へ迫る」接近運動を表現した。カメラ回転が無いため NEON RANGE の yaw/pitch 座標変換より計算はシンプルだが、的ごとに接近速度をランダム化して単調さを避けた。
3. **識別ミス・コンボ・見逃しの三重リスク設計**: 得点源をバグの駆除のみに絞り、(a) 正常パケットの誤射で減点+コンボリセット、(b) バグを駆除せず通過させた場合もコンボリセット、の二方向からプレイヤーの緊張感を作った。スコアは `Math.max(0, ...)` で負値にならないようクランプし、`__GAME__.score` が常に非負整数であることを保証した。
4. **検証は「本物の実行」で行う**: `smoke.mjs` は Node 標準の `vm` 上でインラインスクリプトを実際に実行し、⑥は `finish()` を直接呼ばずに約63秒分のフレームを進めて自然にタイムアップさせ、その後 REPLAY ボタンのリスナーを発火してスコア0・残り60秒への初期化と再進行を確認する。ゲーム側は UI と同じ関数を束ねた `window.__GAME__` フック(`state` / `score` / `timeLeft` / `start`)を公開し、検証専用の別ロジックは持たない。
5. **誤タップガード**: PURGE COMPLETE の瞬間に連打していると即 REPLAY されてしまうため、リザルト表示から 0.6 秒(smoke.mjs の要求する 1 秒以下の範囲内)は再開入力を無視する。
6. **要素取得・時間管理・環境依存の方針**: 要素取得は `document.getElementById` のみを使用(`querySelector` 系は不使用)。時間は `performance.now()` を経由する `requestAnimationFrame` のタイムスタンプのみで管理し、`Date.now()` / `setInterval` / `setTimeout` には依存しない。`AudioContext` は存在チェック+`try/catch` で包み、無い環境でも例外なく完走する。`localStorage` や `matchMedia` は使用していない(NEON RANGE 同様、ベストスコアはセッション内メモリのみ)。
7. **題材の安全性**: 駆除対象は無機質な幾何学ブロック(棘型・丸型)であり、人・生物・実在の名称・ロゴ・歌詞は一切使用していない。血液等の表現なし。金融・法律・医療・政治の要素なし。過度な暴力表現もない(「データのノイズ駆除」という抽象的なメタファーに終始)。

## 未解決事項

- スモークはロジックの実行検証であり、実ブラウザでの描画品質・入力遅延・タッチ操作の触感は自動検証していない(依存ゼロを優先し、Playwright 等の追加は見送った)。
- iOS Safari 実機でアドレスバー分の `innerHeight` 変動が起きた場合、回転直後の 1 フレームだけ古いキャンバスサイズで描画される可能性がある(`resize` イベントで追従はするが、リサイズ完了までの過渡的なズレは残る)。
- 難易度カーブ(接近速度・出現比率の時間変化)は固定値であり、プレイ経過に応じた動的な難易度調整は行っていない。
- ベストスコアはセッション内メモリのみで、タブを閉じると消える(永続化には `localStorage` が使えるが、`file://` 直開き環境での例外リスクを避け今回は見送った)。
